从 AI Infra 到"设计模型"：顶会与 Kimi 路线

> 背景：已跑通第零层（Transformer Block / PyTorch 训练 / 集合通信直觉）。 🧵

---

一、先纠一个误区

"设计模型" ≠ 凭空想一个架构。
顶会论文 95% 是：在强 baseline 上做一个有依据的小改动，用实验证明它更好。
架构创新（如 Transformer→Mamba）是极少数；绝大多数是"某个环节更优"。
所以你要练的不是"想象力"，是：读得懂 → 复现得出 → 找得到 gap → 改得动 → 测得服人。

> 关键：第 4 步的"小"是故意的。改动越小、因果越干净，越容易发。

三、顶会地图（按方向选）

你的甜区：AI Infra 能力 → 冲 MLSys / OSDI / ASPLOS。
这些会 "工程 + 研究" 双栖的人稀缺，正好是你 infra 底子的用武之地（KV Cache / 量化 / 推理系统 / 分布式）。
比硬挤 NLP 主会更容易差异化。

---

四、本科发顶会的现实路径（重要，别被鸡汤骗）

· 单干几乎不可能：需要导师/合作者/算力。
· 现实阶梯：
1. 找组 / 远程 RA（港新教授、国内实验室）
2. 和 PhD / 博后合作，先做二作/三作起步
3. 先投 workshop paper 或挂 arXiv 练手
4. 再冲 main conference

五、Kimi（月之暗面）要什么

1. 强工程：能写 kernel、分布式、推理系统（不是只会调 API）
2. 研究 taste：读过顶会、能提好问题、知道什么值得做
3. 硬证据：顶会 / 开源 / 复现 / 竞赛，至少占一样
