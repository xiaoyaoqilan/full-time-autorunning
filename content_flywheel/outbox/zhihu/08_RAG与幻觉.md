# 08 · RAG 与幻觉：为什么给大模型外挂一个图书馆，它还是会胡说

## 一句话

RAG（检索增强生成）解决的是"**不知道**"，治不了"**说错话**"。幻觉的根源不在知识缺失，而在生成机制本身——下一词预测器没有"我不知道"这个状态。把 RAG 当幻觉解药，是过去两年企业落地最大的认知错位。

---

## 一、先把两个概念劈开

- **知识缺口型错误**：训练数据里没有（新政策、私有文档），模型硬编——**RAG 的正靶子**。
- **生成机制型幻觉**：知识在，但模型仍输出错误内容（编造引用、数字算错、张冠李戴）——**RAG 治不了**，因为问题不在"缺料"在"工艺"。

企业落地里两者的比例常被搞反：大家以为翻车主要是前者，实际大量是后者。

## 二、幻觉的机制根源：为什么"下一词预测"必然会说谎

LLM 的目标函数是最大化下一 token 的似然——**它被训练成永远给出"最像的话"，而不是"最真的话"**。三个推论：

1. **没有"不知道"状态**：训练分布里几乎没有"这个问题我不知道"作为高似然续写（教科书和网页都是确定的语气）。模型对任何问题都会流畅作答——流畅度是文风拟合，不是知识置信度。
2. **采样是概率性的**：temperature>0 时，低概率 token 也有机会被采出；一条低置信但"语言上通顺"的路径会被接下去，错误自我强化（前文错了，后续条件在前文上继续编，越编越顺）。
3. **事实与文采共用同一组权重**：模型没有一个独立的"事实核查模块"，真实性只是语言统计的一部分。

所以幻觉不是 bug，是**训练目标的结构性产物**。要压它，只能改目标（RLHF 里的诚实偏好）、加外部约束（RAG/工具）、或改推理（自我验证）——单靠"多读文档"只能压第一类。

## 三、RAG 的正确解剖：它到底改了什么

RAG pipeline：查询改写 → 检索（向量库 top-k，BM25 混合）→ 拼 prompt → 生成。它做的事只有一件：**把"闭卷考试"改成"开卷考试"**。

有效的前提链条（每一环都会断）：
1. 文档库里**有**答案（覆盖）→ 私有知识缺口型问题成立；
2. 检索**召回了**对的段落（召回率）→ 嵌入模型对专业术语、多跳问题的召回是短板；
3. 模型**读了并服从**检索内容（grounding）→ 模型可能无视上下文、继续用参数记忆作答（尤其当两者冲突时）；
4. 引用**忠实**于检索内容（faithfulness）→ 生成仍可能对原文做自由发挥。

**第 3、4 环就是幻觉的原地复活**。这就是为什么 RAG 上线后错误率下降但不清零——它把开卷考试给了学生，但学生还是会不看书瞎写。

## 四、工程上真正有效的组合拳

| 层 | 手段 | 治什么 |
|----|------|--------|
| 检索 | 混合检索（向量+BM25）、重排序（reranker）、查询改写、多跳分解 | 召回率 |
| 生成 | 严格 grounding 提示（"只根据以下材料回答，没有就说没有"） | 无视上下文 |
| 引用 | 强制逐句引用 + 引用校验器（引用不存在即拒答/重写） | 编造引用 |
| 拒答 | 置信度/检索质量门控：召回分数低 → 直接说不知道 | 硬编 |
| 训练 | RLHF/RLVR 中加入"诚实/拒答奖励"，让"我不知道"成为高回报行为 | 根子上的目标函数 |
| 后验 | 自我一致性（多次采样投票）、NLI 校验（结论是否被检索文档蕴含） | 生成型幻觉 |

其中**最后两条是最接近根子的**：改训练目标（让"不知道"变得有利可图）和加独立校验器（不信任生成器自己）。

## 五、边界与判断

1. **RAG、微调、长上下文是三件不同的事**：RAG 加"可更新的外部知识"，微调改"行为与文风"，长上下文只是把书桌变大——拿微调去塞知识（既贵又易灾难性遗忘）、拿长上下文替代检索（大海捞针注意力会稀释）都是常见错配。
2. **幻觉无法清零，只能工程化管理**：目标函数决定了"永远给最像的答案"。成熟的姿态是像对待概率系统一样对待它：分层错误率、拒答门控、引用审计——**把"防幻觉"变成"验输出"**。
3. 深层判断：幻觉的最终解法不在 RAG，在**可验证性**——让模型的每个断言都能被外部工具校验（计算器、检索、形式验证）。这正是"LLM+验证器"路线（AI4S 第四类）在通用领域的翻版：**信任从"模型说的"迁移到"模型证明的"**。

一句话总结：**RAG 给模型一本开卷资料，幻觉来自它"永远要交卷"的本能。治本能要么改奖励（训练），要么加监考（校验），别指望多塞几本书。**
