# 从 AI Infra 到"设计模型"：顶会与 Kimi 路线

> 背景：已跑通第零层（Transformer Block / PyTorch 训练 / 集合通信直觉）。
> 目标：① 从"复现"转向"设计"；② 冲顶会；③ 进 Kimi（月之暗面）。

---

## 一、先纠一个误区

"设计模型" ≠ 凭空想一个架构。

顶会论文 95% 是：**在强 baseline 上做一个有依据的小改动，用实验证明它更好。**
架构创新（如 Transformer→Mamba）是极少数；绝大多数是"某个环节更优"。

所以你要练的不是"想象力"，是：**读得懂 → 复现得出 → 找得到 gap → 改得动 → 测得服人。**

---

## 二、从"学"到"设计"的 6 步转折

| 步 | 动作 | 验收 |
|----|------|------|
| 1 | 选一个**窄**问题（别一上来"设计大模型"） | 能一句话说清要解决什么 |
| 2 | 复现一个 baseline（nanoGPT / nano-vllm / 小 MoE） | 结果和论文对得上 |
| 3 | 读 20 篇相关论文，列"没解决的" | 找到 1 个真 gap |
| 4 | 提一个**小**改动（一个算子/一个 attention 变体/一个量化策略） | 有理论或直觉依据 |
| 5 | 做 ablation，对比 baseline | 指标有提升且可复现 |
| 6 | 写论文 / 开源 | 别人能跑通你的代码 |

> 关键：第 4 步的"小"是故意的。改动越小、因果越干净，越容易发。

## 三、顶会地图（按方向选）

| 方向 | 顶会 |
|------|------|
| 机器学习 | NeurIPS / ICML / ICLR |
| NLP / LLM | ACL / EMNLP / NAACL |
| 视觉 / 多模态 | CVPR / ICCV / ECCV |
| **系统（AI Infra 最对口）** | **MLSys / OSDI / ASPLOS / FAST / NSDI** |

**你的甜区**：AI Infra 能力 → 冲 **MLSys / OSDI / ASPLOS**。
这些会 "工程 + 研究" 双栖的人稀缺，正好是你 infra 底子的用武之地（KV Cache / 量化 / 推理系统 / 分布式）。
比硬挤 NLP 主会更容易差异化。

## 四、本科发顶会的现实路径（重要，别被鸡汤骗）

- **单干几乎不可能**：需要导师/合作者/算力。
- 现实阶梯：
  1. 找组 / 远程 RA（港新教授、国内实验室）
  2. 和 PhD / 博后合作，先做**二作/三作**起步
  3. 先投 **workshop paper** 或挂 **arXiv** 练手
  4. 再冲 **main conference**
- **周期**：一个完整 cycle（idea→实验→写作→rebuttal）约 **6-9 个月**。
- **本科 4 年能发 1-2 篇一作已非常能打**，不要用它当唯一目标。
- 提分关键：**可复现性 + 强 ablation + 清晰 motivation + 好图**。

## 五、Kimi（月之暗面）要什么

**它的研究方向**：长上下文 / MoE / RL（Kimi k1.5）/ 推理系统（Mooncake）/ 多模态（Kimi-VL）。

**三样硬货，缺一不可**：
1. **强工程**：能写 kernel、分布式、推理系统（不是只会调 API）
2. **研究 taste**：读过顶会、能提好问题、知道什么值得做
3. **硬证据**：顶会 / 开源 / 复现 / 竞赛，至少占一样

**最稳的进入方式**：
- **实习 → 转正**（最现实，校招名额少）
- **内推**（找在里面的人）
- **开源被看见**（GitHub 项目被他们 star/使用）

**你的差异化**：infra + research 双栖。
Kimi 推理系统团队（Mooncake 那批人）最缺的就是"既懂系统又能做研究"的人——你的 AI Infra 路线正好补这个缺口。

| 持续 | 建立可见度 | 每周读论文、写技术博客、GitHub 有货、找远程 RA |
