# 04-算法设计（algo）

> **TL;DR**
> - 并发/重试/判定/评级全部参数与规则的定稿，dev 与 QA 的共同裁判文书。
> - 并发：合约级 4 workers + 节点级串行 failover；NodePool 连续失败 ≥2 冷却 60s 自愈。
> - 失败三分类：超时/429-5xx 走换节点+退避（0.5/1/2s，±20% 抖动，上限 4 次请求）；JSON-RPC error 不重试；revert = 探测失败非红旗。
> - getCode=`0x` 必须写"EOA 或已自毁合约"，不得断言纯 EOA。
> - 字节码 6 条特征，分 strong/weak；weak 需 ≥2 条才合并 1 条 ⚠️。
> - 评级不变式：确定性红旗→❌，启发式仅 ⚠️，**无法确认免费 ⇒ 禁止 ✅**。
> - **谁该读**：改评级逻辑、selector、退避参数前必读；注意 §4.2 大小写匹配规则本身有缺陷（见 05-D1）。


依据：`02-架构评审.md`、`03-任务拆分.md`（T2 卡产出，供 T3/T4/T5/T6 消费）。
约束：Python 3.8+ 仅标准库；所有 selector/接口 ID 硬编码 hex 字面量（标准库无 keccak）；启发式结论一律不作为确定性结论。

## 1. JSON-RPC 批量探测的并发模型

### 1.1 总体结构

```
contracts.txt（22 条）
      │
      ▼
ThreadPoolExecutor(max_workers=4)          # 合约级并发
      │  每个合约一个检查管线（顺序执行其 6 项检查）
      ▼
节点池 NodePool（3 节点，带健康状态）       # 节点级 failover
      │
      ▼
json_rpc_call(endpoint, method, params, timeout=10)
```

- **并发层级**：合约级并发（4 workers）+ 节点级 failover（串行轮换），**不做请求级并发**——22×6≈132 次调用规模下，4 并发已饱和带宽，请求级并发只会放大公共节点限频风险。
- **max_workers=4**：与架构评审一致。dev 可暴露为 argparse 可选参数（`--workers`，默认 4，范围 1~8），但默认值不改。

### 1.2 每节点独立 session

- 标准库无 requests.Session；用 `urllib.request` + 每节点一个 `urllib.request.OpenerDirector`（`build_opener`）实现"独立 session"：
  - 每个 opener 持有自己的默认 headers（`Content-Type: application/json`，User-Agent 标识工具名）、自己的超时配置；
  - 避免节点间共享连接状态，一个节点被限频/封禁不影响其他节点的请求头上下文。
- 简化实现允许：不强制 opener 对象，直接每次 `urlopen(Request(url, headers=...))` 也可接受，但**必须**做到节点状态（失败计数、健康标记）按 endpoint 维度隔离存放在 `NodePool` 中，不使用全局变量。

### 1.3 失败节点自动摘除与轮换

- `NodePool` 维护每个节点的状态：`consecutive_failures`、`cooldown_until`（时间戳）。
- 摘除规则：
  - 单节点**连续失败 ≥2 次**（超时/连接错误/HTTP 5xx）→ 标记不健康，`cooldown_until = now + 60s`，期间 `pick_node()` 跳过它；
  - 冷却期结束后自动重新参与轮换（自愈，不需要手动恢复）；
  - 收到**正常响应（含 JSON-RPC error 响应）即重置**该节点失败计数——JSON-RPC error 是业务层错误，节点本身健康。
- 轮换顺序：固定顺序列表，`pick_node()` 返回第一个健康节点；全部不健康时返回失败次数最少的节点（垂死挣扎）并把下一次退避翻倍。
- 若 3 节点全部进入冷却，直接对当前调用返回 `ERROR` 标记（不无限等待）。

## 2. 重试与退避策略

### 2.1 三种失败情况的分类处理

| 情况 | 判定 | 处理 |
|---|---|---|
| **超时**（socket timeout / HTTP 无响应） | `urllib.error.URLError` / `socket.timeout`，timeout=10s | 按节点失败计数 +1 → 换下一节点重试；指数退避 |
| **429 / 5xx 限频** | HTTP 状态码 429（兼容 503） | 视为节点过载：该节点 +1 失败计数，立即换节点；若拿到 `Retry-After` 头则该节点 cooldown 至少取该值 |
| **节点返回 JSON-RPC error**（如 revert、method not allowed） | 响应含 `error` 字段 | 节点本身健康（重置其失败计数）；**不再换节点重试同一调用**——业务层错误重试无意义；按调用语义处理：eth_call revert = "探测失败"，非红旗 |

### 2.2 指数退避参数

- 退避序列：**0.5s → 1s → 2s**（base=0.5，factor=2，共 3 次重试机会，即单次逻辑调用最多发起 1+3=4 次请求，与架构评审一致）。
- 抖动（jitter）：加 `±20%` 随机抖动（`random.uniform(0.8, 1.2)` 乘以退避值），避免 4 个 worker 同时被限频后同步重试（thundering herd）。
- 重试预算归属：退避计数按**逻辑调用**计，不按节点计——即换节点也消耗重试次数，防止坏节点池拖死单合约 60s 总预算。
- 全部重试耗尽 → 该检查项返回 `CheckResult(status=ERROR)`，管线继续下一项，不抛异常（AC-7）。

### 2.3 单合约总预算

- 每合约管线开始记 `t0`，每项检查前检查 `time.monotonic() - t0 > 60s` → 剩余项直接标"未完成"。
- 注意：正在阻塞中的 RPC 调用不中断（标准库做不到安全取消），等它自然超时（≤10s）后再截断，最坏情况单合约 ~70s，可接受。

## 3. eth_getCode 结果判定规则（确定性）

```
result = eth_getCode(addr)
```

| 返回 | 判定 | 等级属性 |
|---|---|---|
| `"0x"`（空字符串） | **EOA**（普通地址，无代码） | 确定性 |
| `"0x"` 长度 ≥ 2 字节（即 hex 长度 ≥ 6，如 `0x6080...`） | **合约** | 确定性 |
| 边界：`"0x6080"` 这类 < 2 字节的极短代码实际不存在于链上，若出现按合约处理并记录原始值作证据 | 合约（异常情形，留证据） | 确定性 |
| 历史上部署过但已 `selfdestruct` 的合约 | 链上 getCode 同样返回 `0x`，**与 EOA 无法通过 getCode 区分** | 见下 |

**自毁合约判定（getCode 无法区分，需降级处理）**：
- `getCode == 0x` 的地址，本项目**只能判为"EOA 或已自毁合约"**（二合一表述），不得断言为纯 EOA。
- 区分手段（尽力而为，均非 100% 可靠，全部标注启发式）：
  1. **BscScan 可选项**：若配置了 `BSCSCAN_API_KEY`，`getsourcecode` 返回非空 `ABI` 字段或 `CreationCode` → 曾部署过合约 → 判"自毁合约"；返回 `-`/空 → EOA。
  2. **交易历史探测**（不实现，留注释说明）：需要 `eth_getTransactionCount` 为 0 且非 EOA 的假设不成立，标准库下无可靠方案，明确放弃并在报告中说明局限。
- 报告文案：getCode=0x 时输出"该地址无链上代码（EOA，或合约已自毁）"。

## 4. 风险启发式规则（非确定性提示）

### 4.1 总原则

- **所有启发式结论必须携带固定文案**：`⚠️ 启发式判断，非确定性结论，建议人工复核`（写入 `CheckResult.is_heuristic=True` + 报告统一渲染）。
- 启发式疑点只能产生 ⚠️，**永远不能单独产生 ✅**；确定性红旗（getCode 异常除外——getCode 本身只做存在性判定）→ ❌ 由评级引擎处理。

### 4.2 字节码特征匹配方式

对 `eth_getCode` 返回的 hex 字符串（大小写统一转小写后）做**子串/正则匹配**。匹配的是 Solidity 编译产物中的痕迹，不是源码字符串：

| 特征名 | 匹配目标（bytecode hex 中的痕迹） | 红旗含义 | 匹配方式 |
|---|---|---|---|
| `selfdestruct_trace` | `0xff` 操作码在部署字节码运行时部分出现（常见模式：`fe` 禁用后无；出现 `ff` 需人工确认上下文） | 合约可自毁，跑路风险 | 子串匹配 + 人工复核标注（误报率高，弱信号） |
| `ownable_marker` | `Ownable` 合约常量痕迹：错误 selector `0x118c750a`（Ownable: caller is not the owner 的 keccak 前 4 字节） | 有 owner 权限模型，owner 可改规则 | 子串匹配 |
| `blacklist_marker` | 常见黑名单函数名痕迹：`blacklist`、`isBlacklisted`（经 Solidity ABI 编码后函数名以 ASCII 出现在字节码的字符串常量/错误消息区，可小写子串匹配） | 可能存在地址黑名单 | 子串匹配（大小写不敏感） |
| `pause_marker` | `paused`、`pause` 函数名 ASCII 痕迹 | 可暂停 mint | 子串匹配 |
| `mint_price_marker` | `MINT_PRICE`、`mintPrice`、`price` ASCII 痕迹 | 辅助佐证 fee 探测 | 子串匹配（正信号，非红旗） |
| `proxy_pattern` | EIP-1967 槽位相关痕迹：`0x360894a13ba1a3210667c828492db98dca3e2076cc3735a920a3ca505d382bbc` 的截断匹配，或 `delegatecall` 操作码 `f4` | 代理合约，逻辑可被替换 | 子串匹配（`f4` 单独出现误报高，弱信号） |

实现落点（T1 常量区骨架，T4 消费）：

```python
BYTECODE_PATTERNS = [
    # (特征名, 匹配子串/正则, 方向: red-flag|info, 强度: strong|weak, 说明)
    ("selfdestruct_trace", ..., "red_flag", "weak",  "字节码含 0xff 特征，可能可自毁（弱信号）"),
    ("ownable_marker",     "118c750a", "red_flag", "strong", "含 Ownable 权限模型痕迹"),
    ("blacklist_marker",   ..., "red_flag", "medium", "疑似含黑名单机制"),
    ...
]
```

### 4.3 标注与强度分级

- 每条特征命中后在证据字段写入：命中的特征名 + 匹配到的 hex 片段（截断展示前 32 hex 字符）。
- 强度分级：
  - **strong**：可独立支撑一条 ⚠️（如 ownable_marker、proxy_pattern 具体槽位）；
  - **weak**（selfdestruct_trace 的裸 `ff`、孤立的 `f4`）：仅作展示，**不单独计红旗**，多条 weak 叠加可合并为一条 ⚠️（评级引擎规则：≥2 条 weak 命中 → 1 条 ⚠️）。
- 明确写进报告模板：**"特征匹配基于字节码模式，存在误报/漏报可能（如代理合约、内联优化、非常量 price），结论仅供初筛。"**

## 5. 伪代码

### 5.1 节点池与 failover

```python
def rpc_call_with_failover(method, params) -> Result:
    retries = 0
    backoff = 0.5
    while retries <= 3:
        node = pool.pick_node()            # 返回健康节点；全不健康返回最优降级节点
        if node is None:
            return ERROR                   # 节点池整体不可用
        try:
            resp = json_rpc_call(node.endpoint, method, params, timeout=10)
            pool.mark_success(node)        # 重置失败计数
            if "error" in resp:
                return RPC_ERROR(resp["error"])   # 业务错误，不换节点不重试
            return OK(resp["result"])
        except Timeout/URLError/HTTP429/HTTP5xx as e:
            pool.mark_failure(node)        # 连续≥2 → cooldown 60s
            if is_rate_limit(e) and retry_after:
                node.cooldown = max(node.cooldown, retry_after)
            sleep(backoff * uniform(0.8, 1.2))    # 指数退避 + 抖动
            backoff *= 2
            retries += 1
    return ERROR
```

### 5.2 合约检查管线（并发 worker 单元）

```python
def check_one_contract(entry) -> ContractResult:
    t0 = monotonic()
    results = {}
    for check_fn in [check_existence, check_interface, check_fee_heuristics,
                     check_limit_heuristics, check_bytecode_flags, check_bscscan_verified]:
        if monotonic() - t0 > 60:          # 单合约总预算
            results[check_fn.name] = NOT_DONE("超时预算，未执行")
            continue
        try:
            results[check_fn.name] = check_fn(entry.address)
        except Exception as e:             # AC-7：单点失败不中断
            results[check_fn.name] = NOT_DONE(f"异常: {e}")
    return ContractResult(entry, results)

def main_pipeline(entries):
    with ThreadPoolExecutor(max_workers=4) as pool:
        contract_results = list(pool.map(check_one_contract, entries))
    return contract_results
```

### 5.3 getCode 判定

```python
def check_existence(addr) -> CheckResult:
    code = rpc_call_with_failover("eth_getCode", [addr, "latest"])
    if code == "0x":
        return DETERMINISTIC("EOA 或已自毁合约", evidence="eth_getCode → 0x")
    # code 长度（hex 字符数 - 2） / 2 = 字节数
    return DETERMINISTIC("合约", evidence=f"eth_getCode → 0x…{len(code)} hex chars")
```

### 5.4 字节码特征扫描

```python
def check_bytecode_flags(code_hex) -> CheckResult:
    code = code_hex.lower()
    hits = [(name, desc) for (name, pattern, direction, strength, desc) in BYTECODE_PATTERNS
            if pattern in code]
    strong_hits = [h for h in hits if strength_of(h) == "strong"]
    weak_hits  = [h for h in hits if strength_of(h) == "weak"]
    if strong_hits or len(weak_hits) >= 2:
        return HEURISTIC_WARN(hits)        # 强制带"启发式，需人工复核"文案
    return NEUTRAL(hits)                   # weak 命中仅展示
```

## 6. 给 dev 的实现边界说明

- 本文档只定**策略与参数**，不定实现细节：opener 是否复用、NodePool 用 dict 还是 dataclass、CheckResult 字段命名等由 dev 决定。
- 必须遵守的不变式（验收时逐条核对）：
  1. `max_workers=4`、timeout=10s、退避 0.5/1/2s、单合约 60s 预算——参数可 argparse 化但默认值不改；
  2. JSON-RPC error 不换节点重试；网络错误才走 failover + 退避；
  3. getCode=0x 的文案必须是"EOA 或已自毁合约"，不得写"EOA"；
  4. 所有启发式结论带"启发式，需人工复核"文案；无法确认免费 ⇒ 不给 ✅。
