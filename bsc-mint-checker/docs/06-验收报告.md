### 1.1 网络诊断结论（重要，供复现者参考）

- 本机注册表代理为 `127.0.0.1:7890`（FlClash），**经 7890 访问 `bsc-dataseed.binance.org` 正常**（curl 与 urllib 均返回最新块高）。
- 但宿主环境把 `HTTPS_PROXY` 强制覆写为 `http://127.0.0.1:49710`，该代理连不上 binance 节点；urllib 的 `getproxies()` 环境变量优先，导致请求超时后 failover 到 Ankr，而 Ankr 免费端点现已强制 API key。
- **工具侧缺陷**：Ankr 的 `-32000 Unauthorized` 是 JSON-RPC error，按不变式(2)被当作"业务错误"不 failover、不重试，于是认证类节点级故障被放大为全部检查项失败。建议：识别 auth/限流类 error（如 code -32000 含 Unauthorized 字样）时也纳入节点摘除/换节点逻辑，或提供 `--rpc-url` 参数让用户自带节点。
- 复现第 3 轮的正确命令：
  ```bash
  cd bsc-mint-checker
  unset HTTPS_PROXY https_proxy HTTP_PROXY http_proxy ALL_PROXY all_proxy
  python src/check_mint.py contracts.txt -o report.md
  ```

## 9. 本轮新发现缺陷

### 9.1 P0：评级引擎读取的 key 与管线写入的 key 不匹配，评级恒定失准

- **写入**：`check_one_contract` 以函数名作 key 写入，`:644`/`:653` → `cr.results["check_existence"]`、`cr.results["check_fee_heuristics"]` …
- **读取**：`rate_contract` 用中文名读取，`:576` `results.get("存在性")`、`:584` `results.get("铸造费用")`、`:594` 遍历 `("字节码特征","接口类型","铸造限制","BscScan 开源验证")`
- **后果**：所有 `get()` 返回 `None` → `free_confirmed` 恒 False、`has_blocker/has_error` 恒 False → 函数恒返回 `("warn", ["未能探测确认铸造价格为 0，无法确认免费性"])`。
- **定向实测（本地构造 CheckResult 调用 `rate_contract`）**：

  | 场景 | 用管线真实 key（check_*） | 用中文 key（代码预期） |
  |---|---|---|
  | fee = 1 ETH（red_flag=True） | `warn` / 仅 1 条兜底理由 | `warn` / 非零价格理由 + 兜底理由 |
  | 存在性 = EOA/已自毁 | `warn` | `risk` |
  | fee = 探测确认价格 0 | `warn` | `ok` |

- **影响面**：
  1. ✅ 档**永不可达** → PRD 用户故事 3「一眼知道先让 Agent 铸哪几个」功能性失效，0 ✅ 不是启发式限制，是代码缺陷；
  2. ❌ 档**永不可达** → EOA/已自毁等高危不阻断；
  3. 报告 22/22 全 ⚠️、所有"建议"列文案雷同，**统计与结论不可信**（AC-3/AC-5/AC-8 均受污染）；
  4. 该缺陷应自首轮即存在（首轮 22 全 ⚠️ 掩盖了它），**属第 1 轮 QA 漏检，本轮补记**。
- **附带设计缺口**：`CheckResult.red_flag` 字段被 `check_fee_heuristics`/`check_bytecode_flags` 设置，但 `rate_contract` 从未读取该字段 —— 即使 key 修好，fee 非零（如 danta 1 ETH）也只会是 warn，不会升为 ❌，与 PRD 3.2/3.3「隐藏收费→建议跳过」不符。

### 9.2 P1：auth 节点摘除逻辑因 `mark_success` 提前清零而永远不触发

见第 7 节第 3 条实测。最小修法：把 `:301` 的 `_POOL.mark_success(node)` 移到"确认非 auth error"之后；另 `pick_node` 恒返回 `healthy[0]`，缺轮换游标，即使冷却生效也只会固定偏移一个节点。

### 9.3 P2：报告可读性/可信度小事

- 详情中 `证据:` 行与结论行内容大量重复（字节码项几乎整段复读），建议 evidence 只留命中片段。
- 「建议」列固定取 `reasons[0][:60]`（`:702`），一旦有多条红旗，可能截断或取到非关键项；建议优先取具体红旗而非兜底文案。

## 15. 关于「22 条全 ⚠️」与不变式 4 的判定
