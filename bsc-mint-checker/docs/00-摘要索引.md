# 00-摘要索引（bsc-mint-checker）

> 用途：后续会话省 token 的入口。先读本文件；需要细节再按条目指路打开原文。

## 一、全项目总摘要

- **项目**：bsc-mint-checker，BSC 链上"免费 mint"合约批量安全体检 CLI。读 `contracts.txt`（`名称,地址` 每行一条，共 22 条），产出 `report.md` 风险报告。
- **最终状态**：已完结交付。代码 `src/check_mint.py`（842 行，Python 3.8+ 仅标准库，无第三方依赖）；`report.md` 595 行，为 2026-10-28 12:49:47 直连实跑产物。
- **QA 结论**：第 1 轮"有条件通过"（6✅/2⚠️）→ 第 2 轮"不通过"（P0 评级键名错位，评级恒 ⚠️）→ 第 3 轮热修后**通过，8/8 验收标准达成，允许发布**。
- **实跑结果**：22/22 均有结论（❌0 / ⚠️22 / ✅0 / ⏳0，EXIT=0，0 处 Unauthorized）。全部存在（eth_getCode 均有字节码）；类型 17×ERC-721、2×ERC-1155、3×无法识别。
- **核心发现**：2/22（9%）命中"宣称免费实收费"——danta `price()=1 BNB`、AGENT ID card `price()=0.0013 BNB`（1300000000000000 wei），已在汇总表建议列明示金额。
- **关键决策 1**：零第三方 pip 依赖 → selector 全部硬编码 hex（标准库无 keccak）；BscScan 开源验证降级为可选，需 `BSCSCAN_API_KEY`，无 key 时输出"未验证"。
- **关键决策 2**：检查分两级——确定性（getCode 存在性、ERC-165 接口）+ 启发式（费用/上限/字节码特征）；**启发式永远不能单独给 ✅**，无法确认免费一律 ⚠️ 兜底。
- **关键决策 3**：并发参数固定——`max_workers=4`、单次 RPC 10s、退避 0.5/1/2s（±20% 抖动）、单合约 60s 预算；JSON-RPC error 不换节点重试，仅网络错误 failover。
- **关键决策 4**：排序方向以 PRD 为准 ✅→⚠️→❌（第 2 轮曾反转为 ❌ 优先并只改表头，属越权改规格，第 3 轮已回滚）。
- **环境坑（最重要）**：BSC RPC **须直连、不走宿主强制代理**。宿主把 `HTTPS_PROXY` 覆写为 `http://127.0.0.1:49710`（不可达 binance 节点），必须先 `unset HTTPS_PROXY https_proxy HTTP_PROXY http_proxy ALL_PROXY all_proxy`，让 urllib 回落系统注册表代理 7890（FlClash）才能连通 `bsc-dataseed.binance.org`。
- **环境坑 2**：Ankr 免费端点现已强制 API key，返回 `-32000 Unauthorized`；该错误一度被当作"业务错误"不 failover，导致 22 条全失败（已修，auth 错误现纳入节点摘除）。
- **遗留问题（均不阻塞发布）**：P2-1 `red_flag` 只置 ⚠️ 不升 ❌；P2-2 无 BscScan key 时 ✅ 档结构性不可达；P2-3 任一 getter 返回 0 即判"确认免费"，有假免费风险；P2-4 `pick_node` 恒返回首节点、无轮换游标；P2-5 合同级 ⏳ 不可达；P2-6 证据行与结论重复；P2-7 无参运行不自动读 `contracts.txt`（EXIT=2）。
- **设计级遗留**：`05` 的 D1——字节码里函数名是 hex 编码 ASCII，做 lower() 无法匹配驼峰标识符（`mintPrice`/`MINT_PRICE`/`isBlacklisted`），实际只能命中全小写（`pause`/`blacklist`）。
- **对外口径红线**：发布文案不得宣称"能直接告诉你哪些可免费 mint"；实际承诺是"筛出已确认收费/非合约/强红旗的合约，其余标记为需人工复核"。

### docs/01-PRD.md（5.3KB）
- **TL;DR**：定义"是什么、给谁用、做到什么算完"的唯一需求源。
- 背景：推特情报收集约 22 个匿名免费 mint 合约，mint 前需本地批量初筛，避免白付 gas 或被钓鱼。
- 用户：单人加密玩家，懂地址/mint/gas，非审计专家。
- 输入 `contracts.txt`（`名称,地址`，容错空格空行，非法行标"无效输入"）；输出 `report.md`（总览统计 + 按风险排序明细 + 红旗理由）。
- 8 项检查：地址有效性/合约存在性/开源验证/类型识别(721、1155)/费用/铸造限制/权限红旗/黑名单。
- 非功能：纯本地、零第三方依赖、简体中文、单点失败不中断。
- 明确不做：不交易、不签名、不碰私钥、不给投资建议、不做深度审计。
- 8 条 AC，其中 AC-5 规定排序为 ✅→⚠️→❌（后续争议均源于此）。
- **谁何时读**：产品/QA 判断"是否算做完了"时；任何需求变更须回到此文件走流程，不得只改代码或表头。

### docs/04-算法设计.md（13KB，algo 产出）
- **TL;DR**：并发/重试/判定/评级的全部参数与规则，是 dev 与 QA 的共同裁判文书。
- 并发：合约级 4 workers + 节点级串行 failover，不做请求级并发（22×6≈132 次调用）。
- NodePool：连续失败 ≥2 → 冷却 60s 自动自愈；收到 JSON-RPC error 视为节点健康并重置计数。
- 失败分类三档：超时/429-5xx 走 failover+退避（0.5/1/2，±20% 抖动，按逻辑调用计次数，上限 1+3=4 次请求）；JSON-RPC error 不换节点不重试；revert = 探测失败非红旗。
- getCode 判定：`0x` → 必须写"EOA 或已自毁合约"（二者不可区分），不得断言纯 EOA。
- 字节码特征 6 条（selfdestruct_trace/ownable_marker/blacklist_marker/pause_marker/mint_price_marker/proxy_pattern），分 strong/weak；weak 需 ≥2 条才合并 1 条 ⚠️。
- 评级不变式：确定性红旗→❌，启发式→仅 ⚠️，**无法确认免费 ⇒ 禁止 ✅**。
- §6 列 4 条 dev 必守不变式（参数默认值、error 不重试、getCode 文案、启发式文案）。
- **谁何时读**：任何改动评级逻辑、selector、退避参数前必读；QA 判"是否违反设计"时的依据。注意其 §4.2 大小写匹配规则本身有缺陷，见 05-D1。
