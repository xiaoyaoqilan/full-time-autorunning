# PRD：BSC Mint 合约批量安全体检工具（bsc-mint-checker）

> **TL;DR**
> - 需求唯一源：给 22 个匿名"免费 mint"合约做本地批量初筛，避免白付 gas / 被钓鱼。
> - 输入 `contracts.txt`（`名称,地址`，容错空格空行，非法行标"无效输入"）；输出 `report.md`（总览统计 + 排序明细 + 红旗理由）。
> - 8 项检查：地址有效性、合约存在性、代码开源、类型识别(721/1155)、费用、铸造限制、权限红旗、黑名单。
> - 约束：纯本地、零第三方依赖、简体中文、单点失败不中断；不交易/不签名/不碰私钥/不做审计。
> - AC-5 规定明细排序为 ✅→⚠️→❌（第 2 轮曾反转，第 3 轮已回滚）。
> - **谁该读**：产品/QA 判定"是否做完"时；需求变更须回此文件走流程。


## 1. 背景与目标用户

**背景**：用户通过推特情报收集到一批 BSC 链上提供免费 mint 的 NFT 合约（约 22 个）。这些合约来源匿名、质量参差，可能存在钓鱼、隐藏收费、无限铸造成本等风险。用户希望在把目标交给链上 Agent 自动铸造之前，先在本地做一轮批量"安全体检"，快速筛出值得 mint 的合约、剔除明显有问题的。

**目标用户**：
- 个人加密货币玩家（单一用户），使用链上 Agent 执行 mint 操作，但决策前需要一份人工可读的体检报告。
- 用户具备基础的 Web3 概念（地址、mint、gas），但不是合约审计专家。

## 2. 用户故事

1. 作为用户，我把 22 个「名称,地址」丢进 `contracts.txt`，运行一条命令，就能得到一份 markdown 报告，告诉我每个合约该 mint / 该跳过 / 有疑点。
2. 作为用户，我希望工具在 mint 前帮我指出隐藏成本（如宣称免费但实际要付费、mint 上限异常）和常见红旗（如代码未开源可验证、权限可随时改规则），这样我不会白白付 gas 或被钓鱼。
3. 作为用户，我希望报告能按风险从低到高排序并给出结论摘要，让我一眼知道先让 Agent 铸哪几个。

## 3. 功能需求

### 3.1 输入
- 输入文件 `contracts.txt`，每行一条：`名称,合约地址`（以逗号分隔，容忍首尾空格、空行）。
- 支持对地址做基本格式校验（0x 开头、长度 42、十六进制字符）；格式错误的行在报告中标记为"无效输入"并继续处理其余条目。

### 3.2 处理与检查项
对每个合约逐项检查，只定义"检查什么"，不定义实现方式：
- **地址有效性**：地址格式是否合法。
- **合约存在性**：该地址在 BSC 主网上是否为已部署合约（而非空地址/EOA）。
- **代码开源验证**：合约是否在区块浏览器上已验证源码。
- **合约类型识别**：是否为 ERC-721 / ERC-1155 / 其他（含是否支持 mint 入口）。
- **费用检查**：mint 函数是否真的免费（价格为 0），是否存在隐藏的 payable 要求或异常高价。
- **铸造限制**：单地址 mint 上限、总量上限是否合理。
- **权限红旗**：合约 owner/控制方是否存在可随时暂停 mint、修改价格、修改上限等高危权限，且合约是否可升级/可自毁。
- **黑名单/白名单机制**：是否存在能阻止用户 mint 的地址黑名单逻辑。

### 3.3 输出
- 生成一份 markdown 报告（`report.md`），包含：
  - 总览：成功检查数量、失败数量、各风险等级（✅ 建议 mint / ⚠️ 有疑点 / ❌ 建议跳过）数量统计。
  - 明细表：按风险从低到高排序，每个合约一行，含名称、地址、风险等级、命中的红旗摘要。
  - 每个有问题的合约附带简短的理由说明（命中的检查项及原因）。
- CLI 结束时在终端打印报告路径和一句话总结。

### 3.4 命令行交互
- 单命令运行：`python main.py`（或等价入口），自动读取同目录下 `contracts.txt`，无需交互式输入。

## 4. 非功能需求

- **纯本地运行**：所有检查在用户本机完成，不上传合约文件或输入数据到任何自有服务（查询链上/区块浏览器的公开数据除外）。
- **零第三方 pip 依赖**：仅使用 Python 标准库，用户 `python main.py` 即可运行，无需 `pip install`。
- **输出 markdown 报告**：报告为纯 markdown 文本，可在任意编辑器/GitHub 渲染。
- **健壮性**：单个合约检查失败（超时、无法访问等）不应中断整批流程，报告中标注该项检查"未完成"。
- **可读性**：报告使用简体中文。

## 5. 明确不做什么

- **不做交易**：不构造、不广播任何链上交易。
- **不做签名**：不请求、不处理任何钱包签名操作。
- **不涉及私钥**：不读取、不存储、不接触任何私钥、助记词或钱包凭据。
- 不自动执行 mint，不管理钱包/余额，不给出任何投资建议（报告仅为风险检查结论）。
- 不做深度合约形式化审计，只做批量初筛。

## 6. 验收标准

1. 运行 CLI 后，读取 `contracts.txt`（22 条有效记录 + 1 空行），报告覆盖全部 22 条，空行被忽略，不报错。
2. 若某行格式非法（如地址缺 0x 或长度不对），报告中出现"无效输入"标记，其余条目照常检查。
3. 报告文件 `report.md` 生成于项目目录，为合法 markdown，含总览统计、排序明细表、红旗理由三部分。
4. 每个合约至少给出：是否为 BSC 上的合约、是否已验证源码、mint 是否免费三项检查结论。
5. 报告含风险等级统计（✅/⚠️/❌ 数量），且明细按 ✅ → ⚠️ → ❌ 排序。
6. 全程不要求用户输入私钥/助记词，不发起任何交易；代码中不含第三方 import（仅标准库）。
7. 单个合约检查失败时，程序不崩溃，报告中该合约标注检查未完成，最终正常退出。
8. 使用项目附带的 `contracts.txt` 完整跑通一次，报告人工可读、结论符合实际检查结果。
