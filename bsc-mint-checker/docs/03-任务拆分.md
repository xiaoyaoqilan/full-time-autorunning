# 03-任务拆分（splitter）

> **TL;DR**
> - 7 张任务卡 T1~T7，把架构评审落成可执行工单，单文件 `main.py`、Python 3.8+ 仅标准库。
> - T1 常量区+输入解析｜T2 规则设计｜T3 RPC｜T4 检查器｜T5 评级+报告｜T6 并发+CLI｜T7 端到端验收。
> - 关键路径 T1→T3→T4→T5→T6→T7；T2 与 T1/T3 并行，T4 前必须就绪。
> - 每卡含依赖 + DoD，DoD 直接映射 AC-6/AC-7/AC-10 等编号。
> - T2 的规则设计最终落在 `04-算法设计.md`（本文件附录未补）。
> - **谁该读**：追溯责任与依据、或做增量迭代重新派工时。


依据：`01-PRD.md` + `02-架构评审.md`（有条件放行版）。单文件 `main.py`，Python 3.8+ 仅标准库。共 7 张任务卡。

## 任务卡

### T1｜dev｜常量区 + 输入解析模块
- 依赖：无
- 产出：`main.py`（常量区 + 输入模块）
- DoD：
  - 常量区：`RPC_ENDPOINTS`（3 节点）、`SELECTORS`（supportsInterface/price/MINT_PRICE/maxSupply/maxMintAmount/paused 等，硬编码 hex 字面量并注释来源）、`BYTECODE_PATTERNS` 骨架。
  - `parse_contracts_file(path) -> (list[Entry], list[InvalidEntry])`：按行解析 `名称,地址`，容忍首尾空格/空行（空行静默忽略）。
  - `validate_address(addr) -> bool`：`0x` 前缀 + 42 长度 + 十六进制校验（EIP-55 校验和可选）。
  - 空文件/全部无效输入不崩溃，返回空有效列表（对应 AC-10）。

### T2｜algo｜检查规则设计：selector 清单 + 启发式特征库
- 依赖：无（与 T1 并行，产出为设计约定，供 T4/T5 消费）
- 产出：规则设计说明（写入本文件附录或评审记录），最终以常量形式落进 `main.py` 由 T4 执行
- DoD：
  - 每个探测函数的 selector 硬编码值及来源函数签名（如 `price()`→`0x…`、`MINT_PRICE()`、`maxSupply()`、`maxMintAmount()`、`paused()`）。
  - ERC-165 `supportsInterface` 参数：ERC-721=`0x80ac58cd`、ERC-1155=`0xd9b67a26`。
  - 字节码特征清单：`selfdestruct`（0xff 操作码特征）、`onlyOwner` modifier 特征、黑名单/`transferFrom` 限制特征等，每条含（特征名, 匹配方式, 红旗描述）。
  - 明确分级：确定性（getCode / ERC-165）vs 启发式（其余全部）；定义评级规则引擎映射：确定性红旗→❌、启发式疑点→⚠️、无红旗且确认免费→✅、无法确认免费性一律不给 ✅。

### T3｜dev｜RPC 模块
- 依赖：T1（常量区）
- 产出：`main.py` RPC 区段
- DoD：
  - `json_rpc_call(endpoint, method, params, timeout=10)`：urllib + json，10s 超时，异常上抛。
  - `rpc_call_with_failover(method, params)`：3 节点轮询，指数退避 0.5s/1s/2s，全部失败返回 `ERROR` 标记而非抛异常。
  - `eth_get_code(addr) -> str`、`eth_call_const(to_addr, data_hex) -> str`、`decode_uint(hexdata) -> int | None`（空/异常返回 None）。
  - revert 视为"探测失败"，不计红旗（架构风险点 #4）。

### T4｜dev｜检查器函数（消费 T2 规则）
- 依赖：T2（规则）、T3（RPC）
- 产出：`main.py` 检查器区段
- DoD：
  - `check_existence`（getCode：合约/EOA/空，确定性）、`check_interface`（ERC-165，确定性）、`check_fee_heuristics`、`check_limit_heuristics`、`check_bytecode_flags(code_hex)`、`check_bscscan_verified(addr)`（可选，读环境变量 `BSCSCAN_API_KEY`，未配置输出"跳过"，失败不阻塞）。
  - 统一返回 `CheckResult`（dataclass）：结论 + 证据字段（原始 hex/数值/调用结果）+ 确定性/启发式标注。
  - 任一检查器抛异常被捕获并转为"未完成"，不中断流程（AC-7）。

### T5｜dev｜评级引擎 + 报告生成
- 依赖：T4
- 产出：`main.py` 评级与报告区段
- DoD：
  - `rate_contract(results) -> (Level, list[str])`：按 T2 定义的映射规则；启发式结论必须带"⚠️ 启发式，建议人工复核"文案。
  - `generate_report(entries, results, out_path) -> str`：五段结构（头部统计 / ✅⚠️❌未完成 数量 / 明细表排序 / 逐合约详情含证据 / 免责声明）；明细排序按 PRD ✅→⚠️→❌；全简体中文。
  - `print_summary(report_path, stats)`：终端打印报告路径 + 一句话总结。
  - 空输入也能产出合法 markdown（AC-10）。

### T6｜dev｜并发引擎 + CLI 入口
- 依赖：T1、T4、T5
- 产出：`main.py` 并发区段 + `main(argv)`
- DoD：
  - `ThreadPoolExecutor(max_workers=4)` 调度各合约检查管线；单合约总预算 60s，超时终止剩余检查项并标"未完成"。
  - `main(argv)`：argparse 支持 `python main.py [输入文件] [输出文件]`，默认 `contracts.txt`/`report.md`；顶层异常兜底返回非零退出码。
  - `if __name__ == "__main__"` 入口；全程无第三方 import、无任何交易/签名/私钥逻辑（AC-6）。

### T7｜dev｜端到端联调与验收
- 依赖：T6
- 产出：跑通的项目 + `report.md`（附带的 `contracts.txt` 全量实跑结果）
- DoD：
  - 逐条核对 AC-1 ~ AC-10：22 条全覆盖、无效输入标记、报告三部分、三项基础结论、排序与统计、grep 确认无第三方 import、单点失败不崩、空文件合法报告、幂等。
  - 每条结论可人工复核（证据字段齐全，AC-8 修改版）。
  - 用真实 22 条地址完整跑通一次，抽查 ≥3 个合约结论与链上实际一致。

## 关键路径

T1 → T3 → T4 → T5 → T6 → T7（T2 与 T1/T3 并行，T4 前必须就绪）。
