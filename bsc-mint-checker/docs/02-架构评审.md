# 02-架构评审（技术总监 CTO）

> **TL;DR**
> - 结论「有条件放行」，附带范围收敛与技术架构定稿。
> - 否决开源验证为必检项 → 降为可选（需 `BSCSCAN_API_KEY`，无 key 输出"未验证"）。
> - 费用/铸造限制/权限/黑名单无法零依赖可靠实现 → 降为启发式，禁止写成确定性结论。
> - 保留 ERC-165 接口识别（0x80ac58cd / 0xd9b67a26）为确定性检查。
> - 参数定稿：3 节点池、并发 4、timeout 10s、单合约 60s、退避 0.5/1/2s。
> - 核心规则：无法确认免费性的合约一律不给 ✅。
> - **谁该读**：想知道"为什么某些 PRD 要求被砍"时；改范围/加依赖/调架构前必读。


## 第一部分：PRD 评审意见

### 总体结论：**有条件放行**（按下列修改意见收敛后可进入开发）

### 1. 可测性评审（验收标准）

| 条目 | 意见 |
|---|---|
| AC-1（22 条全覆盖、空行忽略） | ✅ 可测，输入文件与验收一致 |
| AC-2（无效输入标记） | ✅ 可测 |
| AC-3（报告三部分结构） | ✅ 可测 |
| AC-4（三项基础结论） | ✅ 可测 |
| AC-5（等级统计与排序） | ✅ 可测 |
| AC-6（无第三方 import） | ✅ 可测（grep import 即可） |
| AC-7（单点失败不崩溃） | ✅ 可测 |
| AC-8（完整跑通、结论符合实际） | ⚠️ **"结论符合实际"不可机器测**。修改为：报告中每条结论必须附带"证据字段"（如 eth_getCode 返回、RPC 调用结果），使结论可人工复核。 |

### 2. 范围评审（收敛性）

**放行项**：3.1 输入、3.2 中的地址有效性/合约存在性、3.3 输出、3.4 CLI、第 4、5 节约束——范围清晰，均可由标准库 + JSON-RPC 实现。

**否决/降级项（按 PRD 原文无法在零依赖约束下可靠实现）**：

1. **❌ 否决"代码开源验证"作为必检项**：BSC 公共 JSON-RPC **没有**源码验证查询能力；BscScan API 需要第三方 HTTP + API Key，与"零依赖、纯公共 RPC"冲突。**修改为**：降级为"尽力而为项"——若用户环境可访问 `https://api.bscscan.com/api` 且提供可选环境变量 `BSCSCAN_API_KEY`，则做开源验证；未提供时报告标注"跳过（未配置 BscScan API Key）"，不作为阻塞检查。对应 AC-4 中"是否已验证源码"允许输出"未检查"。
2. **⚠️ 降级"费用检查 / 铸造限制 / 权限红旗 / 黑名单"**：这些需要 ABI 解码与静态字节码分析，22 个合约 ABI 各异，无法保证准确。**修改为启发式规则**（详见架构）：对已知标准 ABI 尝试 `eth_call` 常量查询（`MINT_PRICE`/`price`/`maxMintAmount` 等），对字节码做特征匹配（`selfdestruct`、`onlyOwner` modifier 特征、`transferFrom` 黑名单特征等），结果一律标注"启发式，需人工确认"。禁止报告把启发式结论写成确定性结论。
3. **✅ 保留"合约类型识别"**：可通过 `eth_call` `supportsInterface(0x80ac58cd / 0xd9b67a26)`（ERC-165）可靠实现，纳入必检项。
4. **PRD 3.4 "python main.py"**：改为一律 `python main.py [输入文件] [输出文件]`，默认值同 PRD。补充而非否决。

### 3. 其他修改意见

- 报告风险等级必须区分"确定性结论"（getCode/ERC-165）与"启发式结论"，⚠️ 默认兜底：无法确认免费性的合约一律不给 ✅。
- 增加 AC-9：对同一地址重复检查结果幂等（除 RPC 波动外）；AC-10：脚本对空文件/全部无效输入也能产出合法报告（总数 0），不崩溃。

## 第二部分：技术架构设计

### 1. 总体架构

```
contracts.txt
     │  parse
     ▼
[输入解析与校验模块] ──► 有效条目列表 / 无效条目记录
     │
     ▼
[并发检查引擎] ── ThreadPoolExecutor ──► 每合约 Checker 管线
     │        (RPC: https://bsc-dataseed.binance.org + 2 个备选节点轮询)
     ▼
[检查器集合]
  ├─ getCodeCheck        : eth_getCode → 合约/EOA/空（确定性）
  ├─ interfaceCheck      : eth_call supportsInterface → ERC-721/1155（确定性）
  ├─ heuristicChecks     : eth_call 常量探测(price/MINT_PRICE/maxSupply/maxMintAmount
  │                        /paused/baseFee…) + 字节码特征匹配(selfdestruct、
  │                        onlyOwner、blacklist 特征)（启发式）
  └─ bscscanVerifyCheck  : 可选，BscScan API getsourcecode（需环境变量 Key）
     │
     ▼
[风险评级模块] ── 规则引擎：确定性红旗→❌；启发式疑点→⚠️；无红旗→✅
     │
     ▼
[报告生成模块] ── report.md（总览统计 / 排序明细表 / 理由说明）
```

### 2. 技术选型与约束

- **Python 3.8+，仅标准库**：`urllib.request`（RPC HTTP）、`json`、`concurrent.futures`、`argparse`、`dataclasses`、`re`、`os`、`sys`、`datetime`。
- **RPC 节点池**：`https://bsc-dataseed.binance.org`、`https://bsc-dataseed1.defibit.io`、`https://rpc.ankr.com/bsc`；请求失败自动切换下一节点（最多 3 次重试）。
- **无 Ethers.js/无 web3.py**：所有 eth_call 参数手工编码（函数 selector = keccak 前 4 字节，selector 常量**硬编码**，避免在标准库内实现 keccak——注意：标准库无 keccak，故所有 selector/supportsInterface 参数以字面量 hex 常量写入代码）。

### 3. 并发与超时策略

- `ThreadPoolExecutor(max_workers=4)`：22 个合约、每合约 ≤6 次 RPC 调用，4 并发已足够且不易触发公共节点限频。
- 单次 RPC 超时 **10s**；单合约总预算 **60s**，超时即终止该合约剩余检查项，标注"检查未完成"。
- 失败重试：节点切换 ×3，指数退避 0.5s/1s/2s；全部失败则该项标记 `ERROR`。
- 不做断点续跑（22 条规模不需要，保持简单）。

### 4. 输出报告结构（report.md）

1. **头部**：生成时间、检查总数、RPC 节点、成功/失败/无效输入统计。
2. **风险统计**：✅ / ⚠️ / ❌ / 未完成 数量。
3. **明细表**（按 ❌ → ⚠️ → ✅ → 未完成 排序，即风险高在前便于先看；如 PRD 坚持 ✅ 前置亦可，开发时按 PRD）：`| 名称 | 地址 | 等级 | 类型 | 免费? | 红旗摘要 |`。
4. **逐合约详情**：每项检查的结论 + 证据（如 `eth_getCode 返回 0x…长度 1234B`、`MINT_PRICE = 0`），启发式结论带"⚠️ 启发式，建议人工复核"标注。
5. **免责声明**：初筛结果非审计，不构成投资建议。

### 5. 模块划分与函数清单（单文件 `main.py`，约 500~700 行）

```python
# ---- 常量区 ----
RPC_ENDPOINTS: list[str]           # 3 个公共节点
SELECTORS: dict[str, str]          # 硬编码 selector: supportsInterface/price/maxSupply/...
BYTECODE_PATTERNS: list[tuple]     # (特征名, 正则/子串, 红旗描述)

# ---- 输入模块 ----
def parse_contracts_file(path) -> tuple[list[Entry], list[InvalidEntry]]
def validate_address(addr) -> bool            # 0x + 40 位 hex + EIP-55 可选校验和

# ---- RPC 模块 ----
def json_rpc_call(endpoint, method, params, timeout=10) -> dict
def rpc_call_with_failover(method, params) -> Any   # 节点轮询 + 重试
def eth_get_code(addr) -> str
def eth_call_const(to_addr, data_hex) -> str  # 返回 return data hex
def decode_uint(hexdata) -> int | None

# ---- 检查器 ----
def check_existence(addr) -> CheckResult      # getCode
def check_interface(addr) -> CheckResult      # ERC165: 721/1155/其他
def check_fee_heuristics(addr) -> CheckResult # price/MINT_PRICE 等探测
def check_limit_heuristics(addr) -> CheckResult # maxSupply/maxMintAmount
def check_bytecode_flags(code_hex) -> CheckResult  # selfdestruct/onlyOwner/blacklist 特征
def check_bscscan_verified(addr) -> CheckResult    # 可选，读 BSCSCAN_API_KEY

# ---- 评级与报告 ----
def rate_contract(results) -> tuple[Level, list[str]]   # 规则引擎
def generate_report(entries, results, out_path) -> str  # 写 report.md，返回路径
def print_summary(report_path, stats) -> None           # 终端一句话总结

# ---- 入口 ----
def main(argv) -> int        # argparse: 输入文件/输出文件/并发数；异常兜底退出码
if __name__ == "__main__": main(sys.argv[1:])
```

### 6. 风险点

| # | 风险 | 缓解 |
|---|---|---|
| 1 | 公共 RPC 限频/不可用 | 3 节点轮询 + 退避重试 + 单点降级标注 |
| 2 | 标准库无 keccak，无法动态算 selector | selector 全部硬编码为字面量常量并注明来源 |
| 3 | 启发式误报/漏报（代理合约、非常量 price 函数） | 结论分级标注确定性/启发式；未知模式一律 ⚠️ 兜底，不给 ✅ |
| 4 | eth_call 可能触发恶意合约 revert/大量 gas | eth_call 为本地模拟不耗 gas；包 try/except，revert 视为"探测失败"非红旗 |
| 5 | BscScan API 在部分地区不可达 | 可选项，失败不阻塞主流程 |
| 6 | 公共节点对 eth_call 批量请求限频 | 并发压到 4 + 每合约调用间不做额外 sleep（规模小，风险可控） |
| 7 | PRD"结论符合实际"依赖链上真实状态 | 报告附原始证据字段，供人工复核 |
