# TL;DR（推理 Infra 方案）
- 形态：单文件 `src/monitor.py`（`urllib` 零依赖），T1 探测鉴权 + T2 离线 mock 均由 infra-serve 交付，dev 不变式由本方案强制约束。
- 探测：健康走 `GET /v1/models` → `GET /health`，可达=2xx 且解析出模型/状态字段，延迟取 `perf_counter` 往返均值；鉴权 `--header` 透传、绝不写死密钥。
- 离线：`--mock` 内置 3 组样例（健康 200 / 压测延迟序列 / 用量样本），字段与真实响应逐一对齐，零 socket 调用全链路可跑。
- 红线：纯只读，method 白名单仅 GET/HEAD，禁 POST 推理写回；4 条 dev 不变式见 §4。

---

## 1) 网关探测设计

### 1.1 探测端点与可达判定
- 探测顺序：`GET /v1/models`（优先，能顺带校验网关已挂模型）→ 回退 `GET /health`。
- 可达判定（满足全部即视为 `reachable`）：
  1. HTTP 状态码 `2xx`；
  2. 响应体可解析（JSON），且 `/v1/models` 含非空 `data[]`、`/health` 含 `status=="ok"/"healthy"`（任一端点满足其一即可判活）；
  3. 往返延迟 `< timeout`（默认 5s）。
- 延迟测量：`t0=time.perf_counter()` 包裹 `urlopen`，`latency_ms=(t1-t0)*1000`；`--count N` 多轮取算术均值输出，单轮失败不计入均值但计入成功率。
- 不可达分级：`URLError`/`socket.timeout` → `UNREACHABLE`；`401` → `AUTH`（提示 `--header`）；`5xx` → `GATEWAY`；均不抛栈，统一收敛到退出码 1（见 02-架构评审 §2.6）。

### 1.2 鉴权 `--header` 透传（R1）
- 入参形态：`--header "Key: Value"`，支持重复传入拼接为 dict；默认空。
- 透传规则：`http_get(url, headers, timeout)` 仅把 `headers` 透传到 `urllib.request.Request(headers=...)`，**不**做任何密钥拼装或默认值注入。
- 红线硬约束：密钥绝不写死在代码/常量/配置文件里；所有鉴权头只能来自命令行参数 `args.header`，详见 §4 不变式 C。
- 401 处置：收到 `HTTPError 401` 即标注 `AUTH` 并提示「尝试 `--header "Authorization: Bearer <token>"`」，不重试、不自动兜底。

### 1.3 `http_get` 只读护栏（公共函数）
- 强制 `method="GET"`（构造 Request 时显式写死，杜绝误用写方法）。
- 构造时**拒绝**任何 `data=` 参数（一旦传入即抛 `ValueError`，在 dev 阶段即暴露误用）。
- 仅 `HEAD` 作为可选只读补充（用于探活不拉响应体），同样禁止 `data`。

## 2) 离线模式 `--mock`（R2）

> 设计原则：mock 数据是一等公民，经与真实响应**完全一致**的解析/统计代码路径，只是数据来源从 socket 换成内置常量。禁止任何 `if args.mock` 特判分支（详见 §4 不变式 B）。

### 2.1 三组数据（字段与真实响应对齐）
内置常量 `MOCK` 提供 3 组样例，结构严格模拟真实网关返回：

**① 健康 200 样例（对应 `/health` + `/v1/models`）**
```json
{
  "endpoint": "/health",
  "status_code": 200,
  "latency_ms": 23.4,
  "body": {"status": "healthy", "uptime_s": 86400, "version": "v1"}
}
{
  "endpoint": "/v1/models",
  "status_code": 200,
  "latency_ms": 31.1,
  "body": {"object": "list", "data": [{"id": "deepseek-chat", "object": "model", "owned_by": "gateway"}]}
}
```

**② 压测延迟样本序列（对应 `bench` 多轮往返）**
```text
latencies_ms = [22, 25, 24, 28, 30, 27, 35, 41, 26, 23, 29, 33, 38, 45, 24, 26, 31, 27, 36, 42, ...]
# 共 100 个样本，均值≈30ms，最近秩法算出 p50≈27 / p95≈44 / p99≈52
# 成功率=100%，throughput=成功数/总耗时
```

**③ 用量样本（对应 `/v1/usage` 或响应头 `x-total-tokens`）**
```json
{
  "source": "mock",
  "date": "2026-10-28",
  "prompt_tokens": 128000,
  "completion_tokens": 86000,
  "total_tokens": 214000,
  "request_count": 100,
  "estimated": false
}
```

### 2.2 全链路离线
- `check --mock`：直接返回 ①，输出可达+延迟，退出 0。
- `bench --mock`：用 ② 序列跑 `quantile()`/`throughput` 统计，输出 p50/p95/p99，零网络。
- `report --mock`：用 ③ 用量样本生成日报，`source` 字段标 `"mock"` 以示非真实。
- 沙箱/CI：`python monitor.py check --mock` 无任何 socket 调用、退出 0、输出可读，满足 T2-DoD 第 3 条。

## 3) 安全红线（纯只读）

1. **method 白名单**：只允许 `GET` / `HEAD`。`http_get` 强制 `method="GET"`；任何 `POST/PUT/DELETE/PATCH` 构造企图在 Request 层即 `ValueError` 拦截。
2. **禁推理写回**：绝对禁止向 `/v1/chat/completions` 等发推理请求；echo 路径需显式 `--allow-echo` + 最小 payload 白名单且默认关闭（属 dev 层能力，infra 层不提供写方法）。
3. **禁副作用**：不写账户、不触发 Webhook、不触发告警、不落盘网关侧任何状态；`report --out` 仅写本地只读产物。
4. **密钥不落代码**：鉴权头只来自 `--header`，不读环境变量、不读配置文件密钥（不变式 C）。
5. **异常不暴露栈**：全局 `try/except` 兜底 → 退出码 3，绝不把内部异常栈打到终端。

---

## 4) dev 必守不变式（4 条）

以下 4 条为交付强约束，任一违反即视为 bug，reviewer/qa 阶段一票否决：

- **A. 探测与解析解耦为纯函数**：`http_get()` 只负责发请求返回 `(status_code, raw_body, latency_ms)` 三元组；解析模型列表/健康状态/延迟统计必须由独立纯函数（如 `parse_models(resp)`、`parse_health(resp)`、`quantile(sorted, p)`）完成，纯函数无 I/O、无全局状态、同输入同输出，可单测。
- **B. mock 数据不经 if 特判**：`--mock` 仅切换「数据来源」（socket ⇄ 内置常量），**不得**出现 `if args.mock: return 硬编码结果` 这类绕过解析/统计逻辑的分支；mock 数据必须流经与真实响应完全相同的解析与统计函数。
- **C. header 只从参数来，不读环境变量密钥**：鉴权头唯一来源是 `args.header`；代码内禁止 `os.environ.get("TOKEN")` / `open(".secret")` 等读取密钥行为，禁止任何硬编码密钥常量。
- **D. 所有请求 method 受限**：全代码库只允许构造 `GET`/`HEAD` 请求；`http_get` 与任何 Request 构造点强制 `method` 白名单校验，传入非白名单 method 直接抛 `ValueError`，从根上杜绝写方法误用。
