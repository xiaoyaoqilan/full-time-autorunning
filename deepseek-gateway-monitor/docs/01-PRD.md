# TL;DR
- 为 `192.168.112.252:8080` 网关做**纯只读**监控台，三个 CLI 交付物：健康检查 / 压测 / token 用量日报。
- 硬约束：纯标准库优先（HTTP 用 `urllib`）、CLI 支持 `--help`、退出码统一约定。
- 核心红线：绝不向网关发送任何会改变状态的请求（无写回、无账户、无告警推送、无 Web 界面）。
- 压测纯只读：仅用 `/health` 或最小 prompt 的 GET/echo 探测，默认保守并发，不压垮网关。
- 验收入口：单命令 `--help` 列出三子命令；全链路零写回。

## 1. 三交付物及验收标准

### 1a. 健康检查 CLI（`check` / `health`）
- 功能：探测网关存活性与延迟基线。
- 探测目标：优先 `/v1/models`（返回模型列表即视为存活），其次 `/health`；两者均失败时报告不可达。
- 输出：
  - 可达性（`OK` / `UNREACHABLE`）与失败原因（连接超时 / DNS / HTTP 非 2xx 等）。
  - 往返延迟（毫秒），可多轮取均值（默认 1 次，可 `--count N`）。
- 参数：`--base-url`（默认 `http://192.168.112.252:8080`）、`--timeout`（默认 5s）、`--count`、`--endpoint`（覆盖默认探测路径）。
- 验收：
  1. 网关可达时输出 `OK` 与延迟数值。
  2. 网关不可达时输出 `UNREACHABLE` 且退出码非 0，不抛未捕获异常。
  3. 仅发安全只读 GET，无 body、无 state-changing 方法。

### 1b. 压测 CLI（`bench` / `stress`）
- 功能：并发只读请求，测延迟分位与吞吐，且不得压垮网关。
- 请求方式：**仅只读 GET / echo**——优先打 `/health` 或 `/v1/models`；若需走 `/v1/chat/completions` 必须显式 `--allow-echo` 且用最小 prompt（如 `{"messages":[{"role":"user","content":"ping"}]}`）、`stream:false`、限制输出 token，且默认关闭。
- 指标：延迟 `p50 / p95 / p99`（毫秒）、请求成功率、吞吐（req/s）、总请求数、并发数。
- 参数：`--base-url`、`--concurrency`（默认 4，上限建议 ≤ 16）、`--requests`（总请求数，默认 100）、`--timeout`、`--duration`（可选，按时间压测）。
- 安全护栏：默认并发与请求数保守；任何超出默认上限需显式传参；提供 `--dry-run` 仅打印计划不发请求。
- 验收：
  1. 输出含 `p50/p95/p99` 延迟与吞吐（req/s）。
  2. 全程只读，无 POST 写状态（echo 路径需显式开启且有最小负载约束）。
  3. 并发受控，不出现网关 5xx 风暴（实测应在阈值内）。

### 1c. token 用量日报（`report` / `usage`）
- 功能：按日汇总 token 用量。
- 数据源：
  - 若网关暴露用量接口（如 `/v1/usage` 或响应头 `x-total-tokens`），则**拉取真实数据**并标注来源。
  - 否则基于压测/探测样本**估算**（按请求数 × 平均 token 估算），输出必须醒目标注「**估算**」字样。
- 输出：可读文本/Markdown 日报（可 `--out report-YYYY-MM-DD.md` 落本地文件，供 Tailscale 远程查看）；含日期、请求数、估算/真实 token 总量、来源说明。
- 参数：`--base-url`、`--date`、`--out`、`--from-bench`（复用最近压测样本估算）。
- 验收：
  1. 有用量接口时取真实值；无接口时给出估算且明确标注「估算」。
  2. 日报可落本地文件，全程无写回网关。

## 2. 明确不做（Out of Scope）
- ❌ 不做任何写回 / POST 状态变更请求（无配置修改、无数据回传）。
- ❌ 不碰账户：无登录、无密钥管理、无身份操作。
- ❌ 不做 Web 界面 / 前端 / 可视化仪表盘。
- ❌ 不做告警推送（无邮件、Webhook、IM 通知）。
- ❌ 不做自动熔断、限流等运维写操作。

## 3. 全局约束
- 语言/运行时：Python 3（标准库优先），HTTP 统一用 `urllib.request`，不引入第三方依赖（如 requests）。
- CLI 入口：单命令 `deepseek-gw-monitor`（或 `python -m monitor`）支持 `--help`，并列出子命令 `check / bench / report`。
- 退出码约定：
  - `0` 成功（含健康检查 OK / 压测完成 / 日报生成）。
  - `1` 业务不可用（网关不可达、压测全失败）。
  - `2` 参数/用法错误（`argparse` 自动）。
  - `3` 致命异常（网络以外未预期错误，需捕获后退出）。
- 可配置：`--base-url` 默认 `http://192.168.112.252:8080`，硬约束地址不可改。
- 输出规范：终端人类可读；日报可 Markdown 落盘。

## 4. 红线（Hard Constraint）
- **纯只读**：绝不向 `192.168.112.252:8080` 发送会改变状态的请求。仅允许 `GET` 存活/模型/健康探测，以及显式开启且受最小负载约束的 echo 类只读请求。
- 任何写方法（POST/PUT/DELETE/PATCH）、账户操作、配置变更一律禁止。
- 压测以「不压垮网关、不影响真实业务流量」为第一准则，默认并发保守。
- 违反红线视为交付失败，一票否决。
