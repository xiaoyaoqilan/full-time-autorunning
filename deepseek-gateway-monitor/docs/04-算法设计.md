# TL;DR（算法设计 · algo）
- 并发压测：`ThreadPoolExecutor(max_workers=concurrency)` + `Semaphore(concurrency)` 硬控并发（默认4、封顶16）；可选 `--rate` 令牌桶（`time.sleep` 节流）防突发。
- 限流速率：默认不限速（concurrency 已兜底），令牌桶公式 `sleep = 1/rate`（每发一个请求补一个令牌，桶容量=concurrency）。
- p 分位：最近秩法 `idx = ceil(p/100 * n) - 1` 取 `sorted[idx]`，确定性、零依赖；超时记为失败样本不计入延迟。
- token 估算：无用量接口时 `估算 = 成功请求数 × (avg_prompt + avg_completion)`（假设经验常数），输出强制带「**估算**」标签。
- dev 不变式：限流默认开启且可关 / p 分位用排序取位不得均值替代 / 估算值必带「估算」标签 / 仅成功样本纳延迟 / 超时=失败 / 全程只读 GET。

## 1) 并发压测模型（避免打垮 192.168.112.252:8080）

### 1.1 线程池 + 信号量
- 驱动：`concurrent.futures.ThreadPoolExecutor(max_workers=concurrency)`。
- worker 数 = `concurrency`；任务数 = `--requests`（默认 100）。每个 worker 循环 `next(pending)` 领取待发请求，直至总数耗尽（非「一任务一线程」），避免线程暴增。
- 硬并发护栏：`sem = threading.Semaphore(concurrency)`，worker 发包前 `sem.acquire()`、收包后 `sem.release()`；`concurrency` 默认 **4**、上限 **16**（argparse `min(16, max(1, args.concurrency))` 封顶）。**绝不**用无界线程池。

### 1.2 全局 QPS 限流（令牌桶 / sleep 节流）
- 可选 `--rate R`（req/s）。维护全局令牌桶：
  - 桶容量 `capacity = concurrency`，令牌 `tokens` 初始化为 `capacity`；
  - 每个请求前按 `now - last_refill` 补令牌：`tokens = min(capacity, tokens + (now-last_refill)*R)`；
  - 若 `tokens < 1`：休眠 `time.sleep((1 - tokens)/R)` 后再补；否则 `tokens -= 1` 放行；
  - 简化等价格式（单令牌/请求）：未达 R 速率时 `time.sleep(1.0 / R)` 节流，等价于每发一个请求强制间隔 `1/R` 秒。
- 默认 `R = None`（不限速），此时仅靠 `Semaphore(concurrency)` 兜底，避免默认即打满网关。

### 1.3 速率守恒（不打垮网关的数学保证）
- 瞬时并发 ≤ `concurrency`（信号量硬限）。
- 长期速率 ≤ `rate`（令牌桶软限，默认关闭）。
- 二者取交集：`实际 QPS ≈ min(concurrency / avg_latency, rate)`。压测目标 `192.168.112.252:8080` 默认只读 `/health`、`/v1/models`，echo 路径需 `--allow-echo` + 最小 payload 白名单，默认关闭。
- `--dry-run` 仅打印计划（worker 数 / 总请求 / 目标端点 / 估算 QPS），零发包。

## 2) 延迟测量与 p 分位

### 2.1 单样本测量
- `t0 = time.perf_counter()` 包裹 `http_get(...)`，`latency_ms = (time.perf_counter() - t0) * 1000`。
- 成功（2xx 且未超时）才记录 `latency_ms`；失败样本仅记 `{ok:False, reason}`，**不纳入延迟序列**。
- 超时（`socket.timeout` / `URLError`）→ 记为**失败样本**（reason=`TIMEOUT`），不计入延迟、不计入 p 分位分母。

### 2.2 p 分位（最近秩法，确定性）
对成功样本延迟升序排序 `S`（长度 `n = len(S)`）：
```
idx = ceil(p/100 * n) - 1
idx = max(0, min(n-1, idx))      # 边界夹紧
quantile = S[idx]
```
- `p50`：`ceil(0.50*n)-1`；`p95`：`ceil(0.95*n)-1`；`p99`：`ceil(0.99*n)-1`。
- **边界处理**：
  - `n == 0`（全部失败）：p 分位返回 `None`，报告标注「无成功样本，p 分位不可用」。
  - `n == 1`：`idx` 夹紧到 `0`，返回唯一值。
  - `p/100*n` 为整数时 `ceil` 后 `-1` 正好落在该秩；非整数向上取整取最近高位秩，符合 nearest-rank 约定。
- 不得用均值/中位数替代分位；`quantile()` 为纯函数，单测可固定序列验证。

### 2.3 吞吐与成功率
- `throughput = 成功数 / wall_clock_s`（wall-clock = 首请求发起到末请求收尾的挂钟秒数）。
- `success_rate = 成功数 / 总请求数`（分母含超时/失败，体现真实降级）。
- 仅成功样本延迟参与 p 分位与均值统计。

## 3) token 用量估算（无用量接口时）

### 3.1 探测真实源（优先）
- `cmd_check` / `cmd_report` 先 `GET /v1/usage`（或读响应头 `x-total-tokens`、`x-prompt-tokens`），2xx 且含数值 → 取真实值，标注「真实（来源 /v1/usage）」。

### 3.2 估算分支（降级，强制标签）
当 401/404/超时或头缺失时进入估算：
```
estimated_tokens = success_requests × (avg_prompt_tokens + avg_completion_tokens)
```
- `success_requests`：本次压测（或 `--from-bench` 复用的本地临时 JSON 样本）成功请求数。
- `avg_prompt_tokens` / `avg_completion_tokens`：**假设经验常数**（默认如 `prompt≈32`、`completion≈8`；echo 开启且带回显内容时按 payload 长度粗估），必须在算法注释与输出中声明为「假设值」。
- 输出**必须**含醒目「**估算**」字样及来源说明（来自压测样本还是经验常数）。`--from-bench` 复用最近压测样本，避免二次探测。
- 公式可扩展为按端点加权：`Σ endpoint_i(success_i × (prompt_i + completion_i))`，初版单常数即可。

## 4) dev 必守不变式（实现校验清单）

1. **限流默认开启且可关**：`Semaphore(concurrency)` 恒生效；`--rate` 默认关闭，但并发信号量不可被 `--no-limit` 等绕过（封顶16 硬约束）。
2. **p 分位用排序取位，不得用均值替代**：禁止以 `mean(latency)` 充当 p95/p99；`quantile()` 必须基于排序最近秩法。
3. **估算值必须带「估算」标签**：凡经 §3.2 公式得出者，输出不可省略「**估算**」字样与来源，不得与真实值混淆。
4. **仅成功样本纳入延迟统计**：超时/失败样本计入成功率分母，但绝不进入 `latency_ms` 序列与 p 分位。
5. **超时即失败样本**：`socket.timeout` / `URLError` 一律记 `TIMEOUT` 失败，不重试、不计入延迟。
6. **全程只读 GET**：所有请求强制 `method="GET"`，构造层拒绝 `data=` 参数；echo 路径需 `--allow-echo` + 最小 payload 白名单，默认关闭，禁写方法、禁账户/Web/告警。
