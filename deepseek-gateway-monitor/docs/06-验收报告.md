## 2. 安全验证（红线）

- **method 白名单（不变式 D）**：`assert_readonly_method` 对 GET/HEAD 放行，对 POST/PUT/DELETE/PATCH 抛 `ValueError` 拦截（实跑验证全部拦截）。
- **无写路径**：全文检索确认不存在 `urlopen(..., data=...)`、`method="POST/PUT/..."` 构造；`probe()` 真实分支硬编码 `method="GET"` 且无 `data=`（`gateway_monitor.py:110-116`）。构造层即杜绝写请求，无法发出任何 state-changing 请求。
- **header 仅来自参数（不变式 C）**：`parse_headers()` 仅解析 `--header` 列表；全文无 `os.environ`、无硬编码 `Bearer`/`api_key`/`secret`/`password`（L657 仅为帮助文案示例）。无密钥硬编码。
- **读响应中的 `data` 字段**（L178）属响应体解析，与请求写无关，安全。
- 结论：红线「纯只读」达成，一票否决项不触发。

## 4. 遗留 / 偏差（不触发红线，建议修复后转正式 PASS）

- **D-1（缺陷，1c.2 未达标）**：`cmd_usage` 解析了 `--out` 但从未 `open(..., "w")` 写入，日报无法落本地文件。需补一段 `if args.out: json.dump/文本写盘`，且应写 Markdown 人类可读格式（PRD 1c 要求「可读文本/Markdown」）。
  - 影响：Tailscale 远程查看本地日报的能力缺失。
- **D-2（偏差，退出码映射）**：PRD §3 约定 2=参数错误、3=致命异常；代码 `_ArgParser.error` 用 3 退出参数错误、`usage` 采集失败用 2。两者与 PRD 互换。功能正确但编号不符，建议对齐 PRD。
- **D-3（偏差，子命令别名）**：PRD §1/§3 期望别名 `check / bench / report`，代码仅实现 `health / bench / usage`。核心功能齐备，但命名与 PRD 验收口径不一致，建议补别名 `add_parser` 同指向。
- **D-4（建议，死代码）**：`cmd_usage` 真实源分支 `return 0` 之后（L489-501）存在不可达重复代码块；`bench --allow-echo` 为 no-op 死开关（reviewer B-2），易误导，建议删除。
- **D-5（已知，需主管决策）**：超时错误标签 `UNREACHABLE`（08 方案）与 `TIMEOUT`（04 不变式5）文档冲突，功能无碍，待主管裁定口径。
