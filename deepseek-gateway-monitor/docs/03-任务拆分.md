# TL;DR
- 单文件 `src/monitor.py`(约 400~600 行,纯标准库,`urllib` 零依赖)交付 3 子命令 `check/bench/report`。
- 拆 7 张任务卡:infra-serve×2(探测鉴权、离线mock)、algo×2(分位吞吐、压测并发)、dev×3(check、report、CLI入口)。
- 已吸收 R1(`--header` 可配)/R2(`--mock` 离线)/R3(退出码分级+`--json`)。
- 关键路径:探测鉴权层 → 压测并发 → CLI 集成;分位算法并行供给 bench/report。
- 红线:仅只读 GET,禁写方法、禁账户/Web/告警;默认并发保守≤4(封顶16)。

---

## T1 · 网关探测与鉴权层
- **负责角色**:infra-serve
- **依赖**:无
- **产出文件**:`src/monitor.py`(`http_get` / `probe` 函数区 + 错误分级)
- **DoD**:
  1. 提供 `http_get(url, headers, timeout)` 强制 `method="GET"`,构造时拒绝 `data=` 参数。
  2. 全覆盖 `try/except`:`URLError`/`socket.timeout`→`UNREACHABLE`、`HTTPError`→区分 `401 AUTH`(提示 `--header`)与 `5xx GATEWAY`。
  3. 支持 R1 `--header "Key: Value"` 可配(默认空),传入后带到所有只读 GET。
  4. 单测覆盖 401/超时/5xx 三态,不抛未捕获异常。

## T2 · 离线 mock 模式
- **负责角色**:infra-serve
- **依赖**:T1(复用 `probe` 接口形态)
- **产出文件**:`src/monitor.py`(`--mock` 分支 + 内置样例数据)
- **DoD**:
  1. `--mock` 返回内置样例:健康 OK+固定延迟、压测 p50/95/99 样本、估算 token 日报。
  2. 三子命令 `check/bench/report` 在 `--mock` 下全链路离线可跑(无任何 socket 调用)。
  3. 沙箱无 Tailscale/CI 下 `python monitor.py check --mock` 退出 0 且输出可读。

## T3 · 延迟分位与吞吐算法
- **负责角色**:algo
- **依赖**:无
- **产出文件**:`src/monitor.py`(`measure_latency` / `quantile` 函数区)
- **DoD**:
  1. `quantile(sorted_latencies, p)` 用最近秩法 `idx=ceil(p/100*n)-1`,支持 p50/95/99,确定性、无第三方依赖。
  2. 吞吐 `=成功数/总wall-clock(s)`;成功率 `=成功数/总请求数`,仅纳入成功样本延迟。
  3. 单元验证已知样本序列的分位与吞吐数值正确。

## T4 · 健康检查 CLI(check)
- **负责角色**:dev
- **依赖**:T1、T2
- **产出文件**:`src/monitor.py`(`cmd_check` + argparse 子命令)
- **DoD**:
  1. 探测顺序 `/v1/models` → `/health` → 均失败报 `UNREACHABLE`+原因。
  2. 支持 `--base-url`(默认 `192.168.112.252:8080` 不可改)、`--timeout`(5s)、`--count N`、`--endpoint` 覆盖。
  3. 输出可达性+往返延迟(ms,多轮均值);不可达退出码 1,不抛栈。

## T5 · 压测 CLI(bench)并发与延迟
- **负责角色**:algo
- **依赖**:T1、T2、T3
- **产出文件**:`src/monitor.py`(`cmd_bench` + ThreadPoolExecutor/Semaphore 区)
- **DoD**:
  1. `ThreadPoolExecutor` + `Semaphore(concurrency)` 硬控并发(默认4、封顶16),worker=concurrency、任务=requests。
  2. 仅打 `/health`、`/v1/models`;echo 路径(`/v1/chat/completions`)需 `--allow-echo` + 最小 payload 白名单(`{"messages":[{"role":"user","content":"ping"}]}`,`stream:false`),默认关闭。
  3. `--requests`(默认100)、`--duration`、`--dry-run`(仅打印计划不发请求)、`--rate`(可选令牌桶节流)。
  4. 输出 p50/p95/p99 延迟、吞吐(req/s)、成功率、总请求、并发;成功<100% 按 R3 降级退出 0 并标注。

## T6 · token 用量日报(report)
- **负责角色**:dev
- **依赖**:T1、T2、T3
- **产出文件**:`src/monitor.py`(`cmd_report` + 估算分支)
- **DoD**:
  1. 先探 `GET /v1/usage` 或响应头 `x-total-tokens`,2xx 含数值取真实值并标注「真实(来源 /v1/usage)」。
  2. 401/404/超时则降级估算 `=请求数×平均单次token`,输出含醒目「**估算**」字样及来源说明。
  3. `--from-bench` 复用最近压测样本(本地临时 JSON)估算;`--date`、`--out YYYY-MM-DD.md` 落盘;全程无写回。

## T7 · CLI 入口/退出码/`--json` 集成
- **负责角色**:dev
- **依赖**:T4、T5、T6
- **产出文件**:`src/monitor.py`(`main` 解析 + 统一 `sys.exit` + `--json`)
- **DoD**:
  1. `argparse` 三子命令 `check/bench/report`,`--help` 列出;退出码 0/1/2/3 统一在 `main` 末尾 `sys.exit`,全局 `try/except` 兜底→3 且不暴露栈。
  2. R3 部分失败语义:成功率<100% 但非全失败 → 退出 0 + 报告「降级」段;错误分级写入报告。
  3. `--json` 输出机器可读(含指标+分级);`python -m monitor` 入口可用。
  4. 全链路零写回校验通过(无 POST/PUT/DELETE/PATCH,无账户/Web/告警)。
