# 公司流水线自动编排器

本地串行编排器：通过 Codex CLI 为每个角色启动独立会话，主管在失败时修复，原角色复验；所有阶段通过后才标记通过。状态和简报保存在项目内，重新运行可续跑。默认最多修复两轮；有条件通过、缺失产物、执行失败均不会视为通过，需要权限或用户决策时停止。

恢复时如发现已通过阶段的产物缺失或为空，会重新执行该阶段并使后续结论失效。QA 阶段经主管修复后，会先重新进行代码审查再验收。Codex 启动失败、退出异常或超时会停止并提示检查运行环境，避免把连接问题交给主管反复修代码。

## 使用

需要已登录、可用的 Codex CLI，以及 Python 3.9 或以上。下面的 Python 路径是当前机器已检测到的路径：

```powershell
$py = 'C:\Users\Lukas\.workbuddy\binaries\python\versions\3.13.12\python.exe'
& $py 'C:\Users\Lukas\WorkBuddy\2026-10-27-16-08-57\company-pipeline-auto\pipeline.py' 'C:\Users\Lukas\WorkBuddy\pipeline-projects\example' --request '在这里写具体需求、范围和验收标准'
```

中断或修复环境后续跑同一项目时，省略 `--request`。状态见项目下 `STATUS.md`，角色产物见 `docs/`，机器状态和日志在 `.pipeline/`。`--max-repairs` 控制每阶段修复轮数，`--timeout` 控制单次会话超时秒数。异常退出留下锁时，确认没有其他实例运行后删除项目内 `.pipeline/run.lock`。

内容飞轮模板：新项目首次运行时添加 `--template content`，每个角色和主管修复时都会收到技术文章、网文、来源核验和人工发布约束。模板是角色指令，不会自动接管现有 `content_flywheel` 文件或强制阻断网络；实际内容引擎仍单独配置和运行。

## 边界

- 这是 Codex CLI 的独立会话编排，不是 WorkBuddy 内建多代理的自动接入。每次调用会消耗账户配额，具体模型和权限由本机 Codex 配置决定。
- 自动判定由角色结果和产物存在性共同决定，不能替代独立的人类审核或证明内容正确。各角色应给出具体证据；生产任务还需要根据业务设置可执行验收检查。
- 本机真实模型连接测试曾遇到请求超时，尚未完成真实端到端验证。外部操作限制目前是角色提示中的要求，并非独立权限拦截，不能作为安全保证。
- 当前版本顺序执行，不支持并行、实时仪表盘、自动跨项目记忆或分布式调度；外部发布、付款、注册账户和用户认证等需要人工处理。
- 使用 `workspace-write`，但模型仍可执行项目内命令。只在可信任务及独立项目目录运行；不要在包含重要资料的目录直接运行。
- `passed` 表示全部角色报告通过且对应文件存在，并非保证产品安全或真实世界可用。`conditional` 不等于通过。
- 中断发生在角色正在修改文件时，下一次会重跑该角色；项目内容不会自动回滚。

## 自检

在本目录运行 `python -m unittest -v`。这些测试使用模拟角色，检查状态、修复、复验及阻塞，不调用模型，也不验证真实模型服务。
