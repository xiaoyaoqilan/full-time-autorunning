# 04 算法设计 · `vram_est` 显存估算

> **TL;DR**
> 1. **核心**：`T = W + G + O + A + OH`（GiB）；`W=P_total·bpp`、`G=P_train·gbpp`、`O=P_train·optbpp`、`A=k·b·seq·hidden·layers·abpp`、`OH=0.5+5%·(W+G+O)`。
> 2. **关键系数**：`bpp{fp32 4, fp16/bf16 2, int8 1, int4 0.5}`；`gbpp{fp32 4, 低精度 2}`；`optbpp{AdamW fp32 12 / fp32 训练 8, AdamW-8bit 6 / 2}`；`k=4`；上下文 `0.5 GiB`、碎片 `5%`。
> 3. **LoRA 只改 G/O 的基数**：`P_train = P_total·ratio`（ratio=0.005 唯一真值），冻结权重按推理态（无梯度、无优化器）；`rank` 不参与计算。
> 4. **反解**：`T(b)` 对 `b` 线性 ⇒ 解析解 `b* = floor((target−F)/a)`，再用 L2 的 `estimate_total` 逐点回退校验，不重写公式。
> 5. **对账**：与 02·2.5.4 手算表全部数值一致（2.64 / 5.9 / ≈111）；发现 3 处需裁决（见 §9），其中 `--target-vram 2 → max_batch=0` 的 DoD 断言在数学上不成立。
> 6. 产出即本文；实现落 `src/vram_est.py`（T04/T05）。

---

## 1. 符号与单位

| 符号 | 含义 | 单位 |
|---|---|---|
| `P_total` | 模型总参数量（全量，含冻结） | 个 |
| `P_train` | 可训练参数量 = `P_total × ratio`（`rank=0` 时 = `P_total`） | 个 |
| `bpp` | 权重每参数字节数（常驻精度） | B/param |
| `gbpp` | 梯度每可训练参数字节数 | B/param |
| `optbpp` | 优化器每可训练参数字节数（含 fp32 master） | B/param |
| `abpp` | 激活每元素字节数 | B/elem |
| `k` | 激活系数（`act_factor`，默认 4） | 份 |
| `b / seq / hidden / layers` | batch、单次前向 token 总数（enc+dec）、hidden 维、**单侧**层数 | — |
| `T / target` | 总显存 / 目标卡显存 | **GiB（2³⁰ B）** |

**单位不变量**：全模型只允许一个换算常量 `GIB = float(2**30)`；JSON 键 `*_gb` 恒表示 GiB（与显卡标称 80GB=81920MiB 口径一致）。

## 2. 五层公式

### 2.1 L2-a 权重 `W`（常驻，全量参数）

```
W_gib = P_total × bpp(precision) / GIB
```

| precision | bpp | 依据 |
|---|---|---|
| fp32 | 4 | 32 bit = 4 B，**确定值**（数据类型位宽） |
| fp16 / bf16 | 2 | 16 bit = 2 B，**确定值** |
| int8 | 1 | 8 bit = 1 B，**确定值**；QLoRA 的量化 scale 开销（≈0.004~0.13 B/param）未计入，对 0.244B 模型 <0.03 GiB |
| int4 | 0.5 | 4 bit = 0.5 B，**确定值**；同上，nf4 双重量化开销未计入 |

### 2.2 L2-b 梯度 `G`（只存在于可训练参数）

```
G_gib = P_train × gbpp(precision) / GIB
```

| precision | gbpp | 依据 |
|---|---|---|
| fp32 | 4 | 梯度 dtype = 参数 dtype，**确定值** |
| fp16 / bf16 | 2 | 纯低精度训练下梯度与参数同精度，**确定值**（不是经验值：dtype 决定） |
| int8 / int4 | 2 | 量化只作用于**冻结**的权重常驻；可训练部分（LoRA adapter / 全量时的参数副本）仍在 fp16/bf16 计算，梯度 2 B，**惯例，未实测** |

> `# 来源：fp32 分支为 dtype 位宽（确定值）；低精度分支为「梯度跟随训练计算精度」惯例，本仓库未实测，误差 ±20%（若改用 AMP + fp32 梯度累加则为 4 B，见 §9-C1）`

### 2.3 L2-c 优化器状态 `O`（只存在于可训练参数）

```
master = 0 if precision == "fp32" else 4          # fp32 主权重副本；fp32 训练时与 W 共用
state  = 8 (AdamW: m,v 各 4 B) | 2 (AdamW-8bit: m,v 各 int8)
optbpp = master + state
O_gib  = P_train × optbpp / GIB
```

| 优化器 | 参数精度 fp32 | fp16 / bf16 / int8 / int4 |
|---|---|---|
| **AdamW**（fp32 状态） | 0 + 8 = **8 B** | 4 + 8 = **12 B** |
| **AdamW-8bit** | 0 + 2 = **2 B** | 4 + 2 = **6 B** |

> `# 来源：AdamW 的 m/v 为 fp32（框架惯例，确定值）；fp32 master 副本为混合精度惯例（确定值级）；AdamW-8bit 的 int8 m/v = 2 B/param，分块 absmax（block=2048、2 个 fp32 scale ≈ 0.004 B/param）忽略不计；bitsandbytes 实际行为未在本仓库实测，误差 ±10%`

**16 B/param 交叉校验**：fp16 训练 + AdamW ⇒ `W 2 + G 2 + O 12 = 16 B/param`，与业界常用的「混合精度 AdamW ≈ 16~20 B/param」一致 —— 这是本系数表自洽性的外部锚点。
`--optimizer` **不新增 CLI 参数**（超出 T05 参数面）：`OPTIMIZER_SPEC` 常量为预留表，默认 `adamw`；将来暴露只需加表键，公式零改动。

### 2.4 L2-d 激活 `A`（随 batch/seq 线性，唯一可压缩项）

```
A_gib = k × b × seq × hidden × layers × abpp / GIB
```

- `k = 4`（`--act-factor` 可调）：含义 = **每 token 每层保留的中间张量份数**（含反向所需），拆解为「attention 输出 1 + MLP 中间 1 + 反向保存的输入 2」。
- `abpp`：fp16/bf16 = 2，fp32 = 4（与 `gbpp` 同表，同一训练精度口径）。
- `layers` 用**单侧**层数（R1），因 `seq` 已含 encoder+decoder 两侧 token，避免双算；Whisper 的 enc/dec 同构（12/12、24/24），此近似误差已被 `k` 的 ±50% 覆盖。

> `# 来源：经验值（本仓库未实测）。依据：Transformer 训练中每层每 token 需同时驻留 attention 输出、MLP 中间张量与反向所需的输入副本，共约 3~5 份；未开 flash-attention 时偏保守、开 gradient checkpointing 时偏激进。误差 ±50%`

### 2.5 L2-e 固定开销 `OH`

```
OH_gib = 0.5 + 0.05 × (W + G + O)
```

| 系数 | 值 | 依据 |
|---|---|---|
| CUDA context + cuBLAS workspace + 驱动预留 | 0.5 GiB | **经验值，未实测**；实测常见 0.3~0.7 GiB，随驱动/CUDA 版本浮动，误差 ±40%（对小模型主导误差） |
| 显存碎片率 | 5% | **经验值，未实测**；PyTorch caching allocator 常见 3%~8% |

**口径**：碎片基数**不含激活**（沿用 02·R4 冻结口径，保手算表可复现）。已知偏差：真实碎片会覆盖激活，本式在 B-A2 场景低估 `0.05 × 1.648 ≈ 0.08 GiB ≈ 总量 3.1%`，已进 §8 误差预算。
（备注：含激活时 `T` 对 `b` 仍是线性的，02「不含激活才能闭式可解」的理由不严格成立，但不改口径——改了会与 02·2.5.4 手算表冲突，见 §9-C3。）

### 2.6 总量与判定

```
T_gib    = W + G + O + A + OH
ratio    = T_gib / target
PASS: ratio <= 0.85 | TIGHT: 0.85 < ratio <= 1.00 | OOM: ratio > 1.00
headroom = target - T_gib
```

不变量：`abs(sum(breakdown.values()) - T_gib) < 1e-6`；端点归属用精确值 `0.85 → PASS`、`1.00 → TIGHT` 各造一例。

## 3. LoRA 场景修正

### 3.1 拆分逻辑（唯一真值 = ratio）

```
ratio     = 0.005 if lora_rank != 0 else 1.0        # --lora-target-ratio，rank=0 视为全量
P_train   = P_total × ratio
P_frozen  = P_total − P_train
```

| 层 | 计算基数 | 冻结部分处理 | 理由 |
|---|---|---|---|
| `W` | `P_total` | 计入（按 `bpp` 常驻） | 冻结权重仍需占用显存，只是不更新 |
| `G` | `P_train` | **不计** | 冻结参数 `requires_grad=False`，无梯度缓冲 |
| `O` | `P_train` | **不计** | 优化器只初始化 `requires_grad` 参数（02·2.6.2 `build_optim_sched`） |
| `A` | 与比例无关，只看 `b/seq/hidden/layers` | 全量参与前向 | 冻结不省激活（除非 checkpointing） |
| `OH` | `W+G+O` | 随 G/O 缩小而缩小 | — |

**`lora_rank` 角色**：不进入任何 `estimate_*`，仅做 (1) `rank==0` 的全量/局部开关、(2) 渲染层的一行一致性提示（"r=8 全挂 ≈ 0.73% ≫ 0.5%，估算偏保守"）。

### 3.2 数值例（Whisper-small，`--params 0.244 --hidden 768 --layers 12 --seq-len 3000 --batch-size 8 --target-vram 24`）

`P_train = 0.244e9 × 0.005 = 1.22e6`

| 场景 | W | G | O | A | OH | T | verdict |
|---|---|---|---|---|---|---|---|
| **fp16 + LoRA(0.5%)** | 0.4545 | 0.00227 | 0.01364 | 1.648 | 0.5235 | **2.642** | PASS (0.11) |
| fp16 + 全量（rank 0） | 0.4545 | 0.4545 | 2.7272 | 1.648 | 0.6817 | **5.966** | PASS (0.25) |
| int4 + LoRA(0.5%) | 0.1136 | 0.00227 | 0.01364 | 1.648 | 0.5165 | **2.294** | PASS (0.10) |
| fp32 + LoRA(0.5%) | 0.9090 | 0.00455 | 0.00909 | 3.296 | 0.5461 | **4.765** | PASS (0.20) |

全量 vs LoRA 差异 **3.32 GiB（+126%）**，其中梯度+优化器从 0.016 → 3.18 GiB，满足 B-A5「显著更大」；B-A5 文档值 5.9 / 3.2 与本表一致（差异仅为四舍五入）。

**为什么 LoRA 下 G/O 可以忽略**：占总量 0.6%，即使 ratio 误差 50% 也只影响 `T` 0.3% —— 这正是「rank 不进公式」的量化理由（02·2.5.3）。

## 4. 激活显存参考数值例（手算可验算）

`A = 4 × b × seq × hidden × layers × 2 B`（fp16/bf16）

**Whisper-small**（hidden 768, layers 12）

| b | seq | 代入 | 字节 | GiB |
|---|---|---|---|---|
| 1 | 1500 | 4·1·1500·768·12·2 | 110,592,000 | **0.103** |
| 1 | 3000 | 4·1·3000·768·12·2 | 221,184,000 | **0.206** |
| 8 | 1500 | 4·8·1500·768·12·2 | 884,736,000 | **0.824** |
| 8 | 3000 | 4·8·3000·768·12·2 | 1,769,472,000 | **1.648** |

**Whisper-medium**（hidden 1024, layers 24）

| b | seq | 代入 | 字节 | GiB |
|---|---|---|---|---|
| 1 | 1500 | 4·1·1500·1024·24·2 | 294,912,000 | **0.275** |
| 1 | 3000 | 4·1·3000·1024·24·2 | 589,824,000 | **0.549** |
| 8 | 3000 | 4·8·3000·1024·24·2 | 4,718,592,000 | **4.394** |

单样本边际成本（求 `max_batch` 用）：small/seq3000 = **0.206 GiB/样本**；medium/seq3000 = **0.549 GiB/样本**。

**medium + LoRA(0.5%) 全量估算**（b=8, seq=3000, target 24）：`W 1.432 + G 0.0072 + O 0.0431 + A 4.394 + OH 0.574 = 6.45 GiB → PASS`，`max_batch ≈ 39`（`2.056 + 39×0.5493 = 23.48 ≤ 24 < 40×0.5493+2.056`）。
结论：**medium 级 LoRA 在 24 GB 卡上激活占 68%，是唯一需要调 `--act-factor` / 缩 `--seq-len` 的项**；small 级在 24 GB 上激活仅占 62% 且总量 2.6 GiB，几乎不会 OOM。

## 5. `max_batch_size` 反解

### 5.1 解析式（初值）

`T(b) = F + a·b`，其中

```
F = W + G + O + OH_base          # OH_base = 0.5 + 0.05×(W+G+O)，与 b 无关
a = k × seq × hidden × layers × abpp / GIB
b* = 0 if target <= F else floor((target − F) / a)
```

`OH` 与 `b` 无关是关键 —— 这是 02 选「碎片基数不含激活」的真正收益（口径换来了 `F` 的常量性）。

### 5.2 回退校验（必须，L4 不得重写公式）

```
b = b*
while b >= 1 and estimate_total(b) > target: b -= 1          # 浮点/取整方向修正
while estimate_total(b+1) <= target and b < MAX_BATCH_CAP: b += 1
```

- `estimate_total(b)` 必须是 L2 五个 `estimate_*` 的组合，**禁止**在这里重写 `F + a·b`；
- 若 `b < 1`（即 `estimate_total(1) > target`）⇒ 输出 `0` + `assumptions` 追加「最小可行配置仍超限，需降 precision / 缩 seq_len / 换卡」；
- `MAX_BATCH_CAP = 4096`（防空卡/巨大 target 下输出无意义大数，`assumptions` 记一条）。

### 5.3 与 L2 的一致性检查（三条断言，建议进 T04 单测）

1. `abs(estimate_total(b*) − (F + a·b*)) < 1e-9` —— 解析式与分项公式同源；
2. `estimate_total(b*) <= target < estimate_total(b*+1)` —— 边界紧贴，无空档；
3. `all(estimate_total(i) <= estimate_total(i+1) for i in 1..b*)` —— 单调性（对本模型恒成立，用于捕获未来把 `OH` 改成非线性时的回归）。

### 5.4 数值例

| 场景 | F | a | target | b* | 校验 |
|---|---|---|---|---|---|
| small, seq3000, fp16, LoRA | 0.994 | 0.206 | 24 | **111** | `0.994+111×0.206=23.86 ≤24 <24.07` ✅ |
| small, seq3000, fp16, LoRA | 0.994 | 0.206 | 80 | **383** | `0.994+383×0.206=79.9 ≤80` ✅ |
| small, seq3000, fp16, LoRA | 0.994 | 0.206 | 2 | **4** | `0.994+4×0.206=1.82 ≤2 <2.03` ⚠️ 见 §9-C2 |
| medium, seq3000, fp16, LoRA | 2.056 | 0.549 | 24 | **39** | `23.48 ≤24 <24.03` ✅ |
| small, seq3000, fp16, LoRA | 0.994 | 0.206 | 0.9 | **0** | `estimate_total(1)=1.20 > 0.9` → 0 + 建议文案 ✅ |

`b*` 与 02·2.5.4「≈111」一致（±5% 容差内）。

## 7. dev 必守不变式（6 条，评审按此打回）

1. **系数单一出处**：所有系数只存在于 §6 的常量表；五个 `estimate_*` 里出现裸数字（`0/1/GIB` 除外）即视为 bug。新增系数必须先在表里加键并写来源注释。
2. **必须带 breakdown 明细**：返回值恒含 `breakdown{weights,grads,optimizer,activations,overhead}`，且 `abs(sum(breakdown) − total_gb) < 1e-6`；只给总数视为未完成（用户无法定位是哪层吃显存）。
3. **不许无依据魔数**：每个系数上方/同行必须有 `# 来源：…`，且「经验值」必须同时出现「未实测」字样与误差幅度（`±xx%`）；禁止「实测于 A100」这类本仓库无法复现的表述（K1 诚信红线）。机械检查：`grep -c "# 来源：" src/vram_est.py` ≥ 系数表条目数。
4. **单位唯一**：只允许 `GIB` 一处换算；任何函数不得再写 `1024**3` / `2**30`；对外键名 `*_gb` 恒指 GiB，文档与 CLI 说明必须写「GiB」而非「GB」。
5. **单调性**：`T` 对 `b / seq / params` 非减，对 `bpp` 非减；`max_batch_size` 必须走回退校验（§5.2），禁止「解析式直接返回」。
6. **纯函数 + 单真值**：`estimate_*` / `verdict` / `max_batch_size` 内无 `print/open/subprocess/时间/随机`，同输入必得同输出（可 golden 到 1e-6）；LoRA 只有 `ratio` 参与计算，`rank` 只允许出现在参数解析与渲染层。

## 8. 误差预算与校准（给 README B 部分用）

| 误差源 | 单层误差 | 对 `T` 的传导 |
|---|---|---|
| `k=4`（激活） | ±50% | B-A2 场景 激活占 62% → **±31%**（即 B-A10 的 ±30% 来源）；medium 场景占 68% → ±34% |
| `CTX_OVERHEAD_GIB=0.5` | ±40%（0.3~0.7） | B-A2 场景 ±0.08 GiB ≈ **±3%**；小模型场景更显著 |
| 碎片基数不含激活 | 系统性 −3%~−4% | 单向低估，可接受 |
| 优化器/量化开销 | ±10% | 影响 `G+O`，LoRA 下 <0.1% |
| **合计（RSS 式）** | — | **±30%~±35%，单向偏低为主 —— 只可用于预筛，不能替代实测** |

**校准三步法（拿到卡后）**

1. `torch.cuda.reset_peak_memory_stats()` → 跑 1 个 step（forward+backward+`optimizer.step()`）→ `peak = torch.cuda.max_memory_allocated() / 2**30`；
2. 用同参数跑 `vram_est --json`，先校 `CTX_OVERHEAD_GIB`：`ctx ≈ peak − (W+G+O) − A(k=4)`（固定 `b=1, seq` 最小点）；
3. 反解激活系数：`k_hat = (peak − W − G − O − ctx − 0.05(W+G+O)) / (b·seq·hidden·layers·abpp/GIB)`；取 3 组（`b=1,2,4`）做最小二乘，写回常量并把误差幅度改成实测值。

## 9. 与 02 / 03 的对账结论（3 处需裁决）

| # | 冲突 | 数学事实 | 建议 |
|---|---|---|---|
| **C1** | T04-DoD1 写死 `GRAD_BPP = 4`（恒 fp32），但 02·2.5.4 手算表用 `1.22e6 × 2 B = 0.002`，B-A5 的 `5.9 / 3.2 GiB` 也按 2 B 算 | 若取 4：LoRA 场景 `T` 2.642→2.645（+0.1%，无感）；**全量场景 `G+O` 3.18→3.64，`T` 5.97→6.36（+6.5%）→ 超 B-A5 的 ±5% 容差** | 采用 **`GRAD_BPP` 随 precision（fp32→4，其余→2）**，与所有下游数值一致；DoD 改一行，`02·2.5.2` 的「梯度恒 fp32」改为「梯度跟随训练精度，fp32 训练为 4」 |
