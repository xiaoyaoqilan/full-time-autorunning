# 00 摘要索引 · train-infra-kit（档案员 archivist 编制）

## 全项目总摘要

- **项目是什么**：给 LLM 算法工程师的轻量训练侧 infra 工具包，三件套 = GPU 快照 CLI（`src/gpu_snapshot.py`）+ 显存估算器（`src/vram_est.py`）+ Whisper+LoRA 训练脚手架（`scaffold/`）。核心约束：两个 CLI 纯标准库零依赖、`--mock`/`--csv-file` 无卡可演示、ssh 全程 argv list 零 `shell=True`。
- **最终验收（QA 两轮）**：第 1 轮 28 通过 + A-A10 有条件通过（fixtures 缺失）+ 2 项 P2 遗留；第 2 轮复验 fixtures 已补、`--csv-file` 实跑 exit 0、bf16 文案已补、D1 关闭 → **30/30 完全通过（放行）**。
- **主管裁决清单**：G-01 mock 由 4 卡 dataclass 改 2 卡 CSV 文本常量（4090 高载 + 3090 空闲，走真解析器）；G-02 退出码 2/3 语义对调（采集失败=2、参数错误=3）；G-03 新增 util 告警第三阈值 90% + `--util-warn` + `--need-gb` 分配建议（水位 0.9）。
- **算法裁决 3 处**：C1 `GRAD_BPP` 随训练精度（fp16=2B），否则全量场景超 B-A5 ±5% 容差；C2 `--target-vram 2` 时 max_batch 真实解为 4 非 0，另加 `--target-vram 0.9` 造「b=1 即 OOM」用例；C3 碎片基数不含激活仍闭式可解，保留口径但把 −3% 系统性低估写进误差预算。
- **D1 裁决**：fp16 路径保留 `model.half()+GradScaler`（与 vram_est「fp16 梯度 2B」口径一致），README 已补「bf16 可用时优先 bf16」，登记项第 2 轮关闭。
- **遗留**：无 GPU/网络环境，`--host` 远程 ssh 采集**未端到端验证**（以 fixtures 纯函数直调 + `--csv-file` 实跑兜底，A-A10 有条件通过后已闭环）；PRD A-A9/B-A8 退出码 2/3 文字回写仍差两行（文档跟踪项，不阻塞）。
- **环境坑**：开发沙箱无 NVIDIA GPU / 无 torch / 无 PyYAML；解释器为受管 Python 3.13.12；文档口径以 docs/09 为最新（3 张变更单），02/03 部分条文已被取代。
